# 摘要与引言模板

## 摘要（五句话）

1. **问题。** `〈场景〉依赖〈某个假设〉；〈某种失效模式〉的影响仍然没有被搞清楚。`
2. **发现。** `我们表明〈因素 A〉可能比〈因素 B〉更重要：在〈点名的条件〉下，〈指标〉从〈A〉变到〈B〉，而〈对照组〉只让它变化了〈C〉。`
3. **机制。** `这个差异来自〈点名的机制〉；〈为什么显而易见的修法救不了它〉。`
4. **设计。** `我们提出〈系统〉，它〈增加了什么〉，并且只在〈检测条件〉和〈方向条件〉同时成立时动作；在测试条件下，〈结果〉。`
5. **边界。** `在〈数据集〉上的评估同时刻画了〈该机制〉的收益与限制：它能〈正面效果〉，但〈它修不了什么〉，并且〈它可能让什么更糟〉。`

检查清单：三个数字；每个形容词都被实验测过；有条件的机制必须带上它的条件；任何来自某批的数字都要带上它的比较对象。

## 引言（六段）

1. **假设。** 这个领域按〈某个信号〉排序；这是大家共享的前提。一段引用簇，不讲历史。
2. **发现 + 贯穿全文的例子。** 一个负载、一组实验、一次反转；两个用同一个因素解释不了的数字。如果这两个数字来自不同批次，就明确写"一个单独的对照实验"。
3. **为什么调参救不了。** 那些显而易见的参数化修法保留了同样的顺序；点出它依赖的性质，并说明为什么重新缩放修不好它。
4. **不同的信号。** 估计器给不出的一个信号；系统；闸门（检测器 + 部署时已知的方向）；检测器沉默时的默认行为。
5. **证据与边界。** 一句话列出评估的几组实验；一句话说明机制什么时候有用、什么时候没用；指向"局限"一节。
6. **贡献。** 三条发现，每条一句，不重复正文已经给过的数字。

反例（不要这样写）：一上来就讲系统；每一段都塞一条局限；摘要和贡献里出现同一个数字；没有做过扫描就说"robust"。
