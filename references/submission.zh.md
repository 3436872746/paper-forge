# 投稿清单（Submission checklist）

**这一页是干什么的**：它是一张投稿前的逐项检查单。从模板、页数、格式审计，到双盲、作者信息、AI 披露和文件命名，一项不落。

**什么时候看它**：你会选会议模板的时候；你在数页数、愁正文超页的时候；你准备打包上传的时候；你要填作者和利益冲突的时候；你用了 LLM 帮忙写稿、不确定要不要披露的时候。

## 1. 用会议当前的模板

**做什么**：从会议官网下载当前模板，整份重新编译，不改模板本身。

- 使用会议**当前**的模板。如果 CFP（Call for Papers，征稿说明）更换了模板家族（例如 ACM -> IEEE），就用新的文档类重新编译；不要手工移植导言区（preamble，`.tex` 开头设置宏包和版式的那一段）。
- 页数限制：正文页 + 仅含参考文献的页（通常 6+1）。参考文献页必须只包含参考文献。
- 双栏、9-10 pt、US Letter，除非 CFP 另有规定。
- 保持文档类的默认版式：不做全局间距（spacing）覆盖。如果正文溢出，就删字，而不是动模板的浮动体间距。
- 额外宏包是正常的（表格、URL、替代文本 alt text）。它们不构成格式违规；更换文档类才是。

**例子**：某会议去年用 ACM 的 `sigconf`，今年改收 IEEE `conference` 格式。做法是新建一份 IEEE 模板，把正文和图逐节粘进去再编译。不要把 ACM 的 `\usepackage` 列表整段搬过去。

**为什么**：模板家族决定页边距、字号和参考文献样式。手工移植几乎一定会带进旧模板的间距设置。

## 2. 机械审计（打包前运行）

**做什么**：用一份干净副本编译，逐项检查下面八个硬指标。

1. 从包的**干净副本**（在别处解压）运行 `pdflatex`。
2. 页数以及参考文献页的位置。
3. overfull box（内容超出栏宽、日志里会报警的行）= 0；LaTeX 错误 = 0。
4. 引用编号：首次出现顺序等于 `.bbl`（BibTeX 生成的参考文献列表文件）顺序；每个 `\cite` 键都存在；没有 `??`。
5. 图/表：编号按首次引用顺序；每个浮动体都被引用过。
6. PDF 元数据（metadata）：双盲时标题/作者留空；没有致谢、没有单位、没有邮箱、没有本地路径。
7. 字体已嵌入；页面尺寸正确。
8. 文件清单：主 .tex、参考文献、图；没有来自旧一轮运行的 .aux/.log/.bbl。

**例子**：把投稿 zip 解压到一个空目录，在那里跑 `pdflatex`。如果只有在你自己的工作目录里才编得过，说明包里缺文件。`.bbl` 也必须随包一起走。

**为什么**：审稿人拿到的是 zip，不是你的工作目录。干净副本才能复现他们的处境。

## 3. 双盲（double-blind）

**做什么**：让 PDF 里找不到任何能认出你身份的信息。

- 自引用（self-citation）用第三人称。
- 提交的 PDF 里不放资助致谢。
- 正文中不放指向自己仓库的链接。
- 作者姓名/单位填进投稿系统，不放进 PDF。

**例子**：要引自己上一篇工作，写"Wang et al. 之前报道……"，不要写"我们之前报道……"。致谢整节从投稿版删掉，等终稿版（camera-ready）再加回来。

**为什么**：审稿人只拿到 PDF。系统里填的作者信息他们看不到，但 PDF 里的一句话能看到。

## 4. 作者与利益冲突（摘要阶段）

**做什么**：在摘要截止前，把作者和 COI 信息一次填全。

- **所有**作者的完整姓名、单位、国家、邮箱。
- 与 TPC（Technical Program Committee，程序委员会）成员的利益冲突（COI：导师/学生、N 年内合著、同单位）。
- 缺失作者或 COI 信息会触发 desk-reject（编辑直接拒稿）；摘要截止之后通常不能更改作者。

**例子**：投稿前把作者名单和每人近 N 年的合著者过一遍，圈出与 TPC 名单重合的人。TPC 名单一般贴在 CFP 页面上，逐人核对一遍再提交。

**为什么**：作者名单在摘要截止后就冻结。少一个人，只能撤稿重投。

## 5. AI 生成内容

**做什么**：决定要不要披露、在哪里披露，并尽早定下来。

查当前的 CFP。典型政策：LLM（large language model，大语言模型）生成的文本/图/代码必须在一个专门的小节里披露（模型、哪些章节、如何使用）；常规的编辑、翻译和检索通常豁免。要早做决定：披露要占篇幅，并且必须放得进参考文献页之前。

**例子**：你用 LLM 润色了方法一节。按典型政策，润色属于常规编辑，通常豁免；如果整段由模型生成，就要在专门小节写明模型名和章节号。

**为什么**：披露段落要占版面，还得排在参考文献页之前。打包时才发现放不下，就得删正文。

## 6. 打包与命名

**做什么**：给每次提交的产物一个能追溯的名字，并留住旧版本。

- 产物命名为 `VENUE_KIND_YYYYMMDD[letter]`；绝不用 "final"。
- 保留上一个产物；不要覆盖你可能需要拿来对比的那个 PDF。
- 打包后，再从 zip 构建一次并记录哈希（hash）。

**例子**：`SOSP_PAPER_20260314a.zip`、`SOSP_PAPER_20260314b.zip`。补投或 rebuttal（答复阶段）之后再递加字母。叫 "final" 的文件，过两周就分不清是哪一版。

**为什么**：哈希（hash，文件内容的指纹）能证明你上传的那份和本地这份完全一样。

## 一页速查

- 用会议当前模板；换模板家族就整份重编。
- 正文页 + 只含参考文献的页，通常 6+1。
- 双栏、9-10 pt、US Letter，除非 CFP 另有规定。
- 不覆盖模板的全局间距；超页就删字。
- 打包前从干净副本跑一遍，overfull box 和 LaTeX 错误都要为 0。
- 每张图表都被引用过，编号按首次引用顺序。
- 双盲版 PDF 不留姓名、单位、邮箱、致谢、仓库链接。
- 摘要截止前填全所有作者和 COI。
- 用了 LLM 生成内容，先查 CFP，早写披露。
- 产物按 `VENUE_KIND_YYYYMMDD[letter]` 命名，绝不用 final。
