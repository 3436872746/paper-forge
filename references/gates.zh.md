# 闸门与规则

在交付一条命令、一个批次（batch）或一个论断之前，需要经过九道闸门（gate）。每一道都在这里，是因为它曾被违反过一次，而那次违反是无声的。

## A — 合成数据试运行（synthetic dry run）
给 summariser/verdict/controller 逻辑喂一个你知道答案的输入。
例如：一张中位数显而易见的合成表；一次 oracle 臂（arm）必然胜出的回放（replay）；一个在字段已知的两行上运行的解析器。
如果一条控制路径（control path）无法试运行，它就还没有就绪。

## B — 安慰剂/零效应臂（placebo / zero-effect arm）
每个实验都需要一个可证明无法对自变量（independent variable）作出响应的臂（相同的副本、打乱的键（shuffled keys）、空操作策略（no-op policy））。用指标自身的单位度量它的离散程度。这个离散程度就是地板（floor）。
- 两个相同的臂：地板 = 每轮配对偏差（paired deviation）的最大值。
- 三个臂：地板 = 所有配对之间每轮离散程度的最大值。
低于地板的东西都不是差异——不是"小"，也不是"有趋势"。

## C — 同状态原则（same-state principle）
任何由读数计算出的参数，都必须在它将要作用的那一个*同一状态*下计算。来自预热（warm-up）、不同负载或不同批次的校准，都不是同一状态。
典型失败：用在饱和期间测得的速率去标记一次非饱和运行；把一个在一个工作负载上校准的预测器应用到另一个工作负载上，却不说明这一点。

## D — 判据与其历史取值（criterion vs its historical value）
当协议说"稳定即停止"/"第一个判定胜出"/"三次一致之后"，要实现的是判据，而不是启发它的那次运行里的常数。硬编码的 `12`、`n=5`、`0.25` 都是嫌疑对象。

## E — 指标与目的相符（metric matches purpose）
写下这个实验存在的目的是推动哪个指标，然后检查它是否在自动审计清单里。一次运行因为审计检查的是另一个指标而"通过"，那不算通过。

## F — 第二个变量（second variable）
在把原因归于 X 之前，列出各臂之间发生变化的所有其他东西（负载、批次构成、K、预热、硬件）。如果变了两样，你得到的是一种相关，而不是一个原因。

## G — 源文件与转述（source vs retelling）
写进论文的每个数字都由脚本从原始文件重新计算。"看起来合理"正是两个无法复现的数字通过第一天检查的方式。
另外：过滤值（而不只是列名）在使用之前必须对照真实的数据域检查。

## H — 关于代码或命令效果的断言（assertion about code or command effect）
任何形如"这段代码做 X"或"这会产生 Y"的句子，都需要先做一次 grep 或一次试运行。读注释不是读代码。

## I — 试运行契约（dry-run contract）
一个会启动引擎、发送请求或写出输出的"试运行"不是试运行。在调用之前声明脚本能触碰什么；优先用 `DRY=1` 加上一个在第一次外部调用之前就退出的硬性守卫。

# 规则

1. 批次运行期间，只读取已经在磁盘上的文件。不重启、不探测、不起会发送请求的监视进程。
2. 重跑一个批次需要一个显式的、不同的输出目录。默认值会无声地覆盖。
3. 搬运/归档数据用复制。绝不要重命名 git 跟踪的目录。
4. 从记忆里抄一个路径或一个参数名之前，先 `ls`/`grep`。
5. 好得不像真的数字先当作失败：延迟接近零、失败数恰好为零、吞吐跳了一个数量级。
6. "写了"不等于"跑了"。写完一个批次或一个修复之后，执行一次；判据是文件时间戳比脚本新，且没有旧字符串残留。
7. 改动一个数据结构之前，grep 它的每一个读取方。
8. 段落/行索引要现场查，绝不从导出文件里复制。
9. 引擎侧属性（模型、量化、块大小、并发数）必须声明、在运行前守卫、并记录进 `meta.txt`。
10. 按 pidfile 里的 PID 杀进程，先 `pgrep -af`；杀完之后再检查一次。在共享机器上绝不用宽模式。`setsid ... &` 返回 "Done" 是父进程退出，不是批次结束。
11. 清理范围 = 只有本次会话创建并打了标记的东西。如果不确定是谁做的，报告清单而不是删除。
12. "只读"的声明必须由被调用方的结构来保证：在导入或运行它之前检查有没有 `__main__` 守卫 / 写标志。
13. 环境变量不会从 Unix shell 传到 Windows 可执行文件。传参数，或者运行前把选中的批次打印出来。
14. 在共享机器上，宽模式 `pkill -f` 是一起事故。用 pidfile 和端口。

# 病型（认出形状，而不是认出个例）

- **A — 把一条活的规则冻结成字面量。** 注释解释了一个机制，而代码只实现了一半；一个新的自变量需要它所有的落点。
- **B — 在参数所作用状态之外的状态下读取该参数。**
- **C — 在它所依赖的东西还不存在时就定义/检查它。**
- **D — 编造结论的判定逻辑**（在错误的指标上通过，把缺失的条件当作已满足）。
- **E — 把原因归于两个一起变动的变量中的一个。**
- **F — 凭记忆断言，不回到源头。**
- **G — 建立在坏数据之上；最后得出一个过宽的主张。**
- **H — 侵入一个正在运行的系统。**
- **I — 环境/操作层**（路径、shell、编码、页数限制）。

遇到一个新 bug 时，给它的形状命名。同一个形状会在两周后以另一个名字回来。
