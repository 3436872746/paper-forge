## 1. academic-research-skills

**采纳**

- 每次运行前一个**失败即关闭（fail-closed）的声明**：该技能会问这次运行使用哪些实验，即使是纯文献任务，这样"没有实验"是一个被记录下来的答案，而不是一个静默的默认值。
- **到主张级别的来源判定（provenance verdicts）**，四种结果：aligned / overstated / not supported / provenance insufficient。该检查判定主张与证据之间的链接——从不判定实验本身是否正确。
- **引用定位 + 可选的审计**：抓取原文并追问句子是否真的被支持；标记"主张未被支持""伪造的参考文献""无锚点的引用"。
- **审稿人是只读的**，产出受准则约束的叙述，绝不产出映射到接收/拒稿的数值总分。
- **反谄媚协议（anti-sycophancy）**：给每条 rebuttal 打 1–5 分，只在 ≥4 时让步，不允许连续让步，跟踪让步率。
- 每个任务都**声明数据访问级别**（raw / redacted / verified only，即原始 / 脱敏 / 仅核验）。
- **诚实的限度**：可复现性锁（reproducibility lock）被记录为配置文档，而不是重放保证。

**未采纳**：13/12/10 个 agent 的编排、跨模型交接信封（handoff envelopes）、模型分级（model tiering）、分发渠道矩阵。

## 2. claude-skills（宽目录）

**采纳**

- 工具必须能干净地跑 `--help`，并且**零依赖**（只用标准库）。
- 一项**"会不会触发"测试**：用一个措辞朴素的问题问该技能，并记录它是否触发——一套便宜的触发测试集，公开出来而不是只作声称。
- **人类闸门**：一个计划在一位*具名*的人审阅过、且没有未解决的阻塞项之前不算关闭。
- **运行取证（run forensics）**：把 agent 声称自己做了什么，与它实际做了什么的记录（transcript）作对比。
- **有证据追溯的编辑**：只有在会话历史支持该改动时，才改流程。
- 任何写入之前，一个固定的**讨论 → 映射 → 分解 → 执行 → 验证**循环。

**未采纳**：411 个技能的广度、marketplace 打包、persona theatre（人设戏法）、"tier"式品牌化。

## 3. ARIS（Auto-Research-In-Sleep）

**采纳**

- **四层审计链，所有权分离**：代码完整性 → 结果意味着什么主张 → 论文正确报告了那个数字 → 引用支持那句话。执行者从不判定自己的完整性。
- **保障（assurance）作为第二根轴**：努力程度（effort）缩放广度；保障级别（草稿 vs 投稿）决定审计是否阻断。在投稿时，一个失败的审计会阻断"ready"标签。
- **每轮都是全新上下文的审阅者**，绝不延续线程，也不把修复摘要交给审阅者。
- **持久化的循环状态**加上硬上限：最大轮次、一个算力天花板（超过它则跳过工作并标记）、"优先重新表述而不是新实验"。
- **主张–证据矩阵**先于正文产出。
- **杀招论证闸门（kill-argument gate）**：一次 pass 写出最强的拒稿备忘；一位独立裁决者（不是辩护方）把每一点分类为已答复 / 部分答复 / 未解决，并附 file:line。
- **复述回归**：每轮修复之后，重新检查主张陈述没有漂移。
- **编辑白名单**用于修订轮：允许的路径、禁止的操作（新引用、新数值主张）、每轮 diff 闸门、最大编辑数。
- **失败是一等公民**：失败的想法变成一份禁列（banlist），为下一轮构思提供种子。
- 每条证明性主张都打标签：已证明 / 引入（imported）/ 猜想 / 已修补 / 无支撑。

**未采纳**：向特定厂商的跨模型路由、通宵自动驾驶（overnight autopilot）、87 个技能的广度、自我改写的元优化。

## 4. AI-Research-SKILLs

**采纳**

- **渐进式披露（progressive disclosure）**：一个短的 `SKILL.md`（何时使用、快速模式、链接）加上一个按需获取的 `references/` 包——被加载的指令保持很小。
- 研究被记录为一个**可遍历的产物目录**（traversable artifact directory），而不只是一份散文报告：主张、探索图（exploration graph）、证据、代码桩（code stubs）。
- **会话尾声**：会话结束时，把决定、实验、死胡同与转向写入那个目录，并按来源标注（user / ai-suggested / ai-executed / user-revised）。
- **跨六个具名维度的严谨性评审**：证据相关性、可证伪性、范围校准、论证连贯性、探索完整性、方法学严谨性——按严重度排序，而不是给一个总分。
- **两个循环**：内循环修复当前的东西，外循环周期性追问问题是否仍然是那个对的问题。
- 零结果是内容，不是附录。
- 构思通过**显式透镜（explicit lenses）**，而不是"自由头脑风暴"。
- 作图是与撰写散文分离的一个技能。

**未采纳**：框架手册（serving/training 栈）、安装器、常开运行、"自主研究"式营销。

## 5. Research-Paper-Writing-Skills

**采纳**

- **按章节切分的参考材料**：指导按章节获取，而不是一整章巨大的写作教程。
- **主张–证据对齐作为独立任务**，与润色文字分开。
- **从审稿人席位出发的投稿前自审**，而不是从作者席位。
- 可移植打包：一个 `SKILL.md` + `references/` 目录树，无运行时。
- 一个**署名头（attribution header）**，说明是谁的知识、打包者添加了什么。

**未采纳**：厂商的 agent 元数据文件。

## 6. Agentero

**采纳**

- 先说清**分工**：人提出问题、判断价值、深读、下结论；agent 做批量检索、元数据、抽取、初轮摘要。
- **先抽取再阅读**：在任何模型读论文之前，把 PDF 的公式、伪代码和表格转成 Markdown/LaTeX；原始双栏 PDF 解析是幻觉来源。
- **上下文组装作为一等产物**：论文 + 笔记 + 过往交互放在一处。
- 从**论文自己的参考文献列表**建引用图；用 BibTeX 作交换格式。
- 迁移保留标签、笔记与附件——来源信息（provenance）在搬迁后仍然存活。

**未采纳**：桌面 GUI、本地模型推荐、厂商镜像。

## 7. paperdebugger

**采纳**

- **研究 → 批评 → 修订作为三个独立的 pass**，绝不是一次性"帮我改好论文"。
- **引用核验作为一个显式阶段**，而不是一个指望。
- **默认只读**：工具提建议，人按按钮。
- 反馈是**锚定到确切句子的行内评论**，不是聊天。
- 一个**提示词库**：每个任务有具名的可复用模板。
- **按章节的修订 pass**，而不是一条全局风格指令。

**未采纳**：Chrome/Overleaf 绑定、Go 微服务栈、API 耦合。

## 8. qinyan-academic-skills

**采纳**

- **手稿每个阶段一个技能，每个技能声明一个主产出**——在写指令之前先命名交付物。
- **润色保留意义**，并运行一项反夸大检查；一次改写不得悄悄把主张加强。
- 评审发现上有**稳定的问题标识符**，使第 2 轮能证明每个早先的发现都已被处理或有意拒绝。
- **评审（发现问题）≠ 评估（给问题排优先级）**；产出是一个排序的、可追溯的清单。
- 图导出与**预检校验是一步**：一张图在通过校验之前不算完成。
- **感知估计量（estimand-aware）的统计**：在选择检验之前先命名被估计的量。
- **报告审计**作为与分析分离的一项活动：把稿件中的数字对照计划重新核对。

**未采纳**：187 个技能的广度、`curl | bash` 安装、"Nature 风格"的标签。

## 9. ai-research-skills

**采纳**

- **防泄漏 schema**：一条没有证据产物（artifact）的主张被强制为 `status: gap` 并写明理由；它不能被标成 `supported`。
- **在选定题目之前的三闸判定**：缺口是否仍然敞开、补上它是否是真正的贡献、在剩余时间里是否可行——每一项都有判定与理由。
- **类型化交接（typed handoffs）**：每个阶段的产出是下一阶段的输入，并携带回溯到它所服务的那个缺口的来源信息。
- 只读工作自动进行；**语义验收是一个显式的人类闸门**。
- 每个阶段都有**范例产物（worked-example artifacts）**，而不是文字描述。
- 时间包络（time envelopes）被标为观测值，而不是基准测试值。
- 一个明确的局限段，说明哪些**不**由机器检查。

**未采纳**：运行时依赖、完整编排器、Zotero/Obsidian 耦合。

## 10. agent-research-skills

**采纳**

- **反向可追溯作为硬规则**：PDF 里的每个数字都链回产生它的代码。
- **有界循环**而不是"继续试"：固定重试次数、固定评审轮数、固定新颖性检索轮数。
- **渐进式实验阶梯**：实现 → 调优 → 研究 → 消融，使消融是被计划的，而不是在结果到来之后才补上的。
- **表格生成把报告约定编码进去**（加粗最优、显著性标记、多数据集布局）写进脚本，而不是写进散文。
- **图反馈循环**：在接受一张图之前，先把它作为图像查看一遍。
- 对照一个真实会议的表单做自审，配多个审稿人人设与一次元评审（meta-review）。
- 编译是工作流的一部分，带一次自动纠错 pass。
- **跨产物一致性**（伪代码 vs 图、数学 vs 代码）是它自己的一个步骤。

**未采纳**：仓库挖掘技能、全局安装器、把密钥存在 home 文件里。

## 我们实际保留下来的十二条规则

1. **没有人审计自己的工作。** 跑实验的、写稿的、核数字的是各自独立的 pass；审阅线程每轮都重新开始。
2. **没有证据就是缺口。** 一条没有具名证据产物的主张被强制为 `gap`，并附理由。
3. **主张状态是一个枚举（enum）**，不是一种感觉：aligned / overstated / not supported / insufficient。
4. **审计这条链，而不是审这篇论文**：代码完整性 → 结果意味着什么主张 → 论文报告那个数字 → 引用支持那句话。
5. **每个数字都能追溯到文件与脚本**，投稿前机械核对。
6. **在一位具名的人类闸门通过之前保持只读**；编辑是让人选择的插入。
7. **批评是与修订分开的一次 pass**，修订又与插入分开。
8. **稳定的问题编号**，使后面的轮次能证明每个发现都被处理过。
9. **给每个循环设边界**：最大轮次、算力天花板、编辑白名单；优先用更便宜的重新表述代替新实验。
10. **记录死胡同与转向**，附来源信息，因为零结果是原材料。
11. **润色可以改写措辞，但绝不能加强**一条主张。
12. **说明这项检查无法确立什么**；把限度标注在与结果同一页。
