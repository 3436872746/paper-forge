### 1. Automatic and Universal Prompt Injection Attacks against Large Language Models (arXiv 2024)
- **问题（Problem）：** 提示注入（prompt injection）研究缺少一个统一目标，即攻击究竟想达成什么，并且依赖手工构造的提示，因此健壮性评估既不全面也不可比。
- **假设（Assumption）：** 少量经过优化的注入样本能够泛化到未见过的测试输入，并在防御措施下依然有效——也就是说，攻击发生时可以通过 LLM 集成应用获得梯度。
- **机制（Mechanism）：** 一个统一框架，把攻击目标形式化；外加一种自动化的基于梯度的方法，用来生成高效且通用的提示注入数据。
- **证据（Evidence）：** 基准式评估，与基线和防御方法对比；五个训练样本（相当于测试数据的 0.3%）即达到优于基线的性能。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 在评估防御时，用自动的基于梯度优化器来驱动攻击，而不是用固定的手写攻击集；手工构造的攻击集会系统性地高估健壮性。
- **一句话卖点（Pitch）：** 提示注入看起来没有实际那么危险，是因为攻击一直是临时的——少量优化样本就暴露了这个缺口。

### 2. Detecting Prompt Injection Attacks Against Application Using Classifiers (arXiv 2025)
- **问题（Problem）：** 提示注入危及 LLM 集成 Web 应用和关键系统的安全性与稳定性。
- **假设（Assumption）：** 恶意提示可以由从真实攻击提交中整理出的语料库学到的特征与良性提示区分开。
- **机制（Mechanism）：** 从 HackAPrompt Playground Submissions 语料库整理并增强一个数据集，然后训练 LSTM、前馈神经网络、随机森林和朴素贝叶斯分类器来标记恶意提示。
- **证据（Evidence）：** 在整理后的语料及其增强版本上做数据集/基准评估；摘要未给出定量结果。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 从众包的、真实的对抗输入池出发并加以增强，而不是收集全新数据——这样一个廉价的分类器过滤器就能上线，而不必改动模型权重。
- **一句话卖点（Pitch）：** 一份整理并增强过的注入语料库加上标准分类器，就足以检测并缓解针对 LLM Web 应用的攻击。

### 3. SecAlign: Defending Against Prompt Injection with Preference Optimization (CCS 2024)
- **问题（Problem）：** LLM 会读取外部数据——文档、网页检索、API 结果——而在其中植入的对抗提示可以覆盖系统原本的指令。
- **假设（Assumption）：** 对同一份被污染的输入，一个被训练成偏好安全补全而非不安全补全的模型，在面对远比训练时更复杂的攻击时仍会保持这种偏好。
- **机制（Mechanism）：** 构造一个偏好数据集：提示注入的输入配上安全输出（回答合法指令）和不安全输出（回答注入），然后在其上做偏好优化。
- **证据（Evidence）：** 在多种提示注入上的实证评估；即使面对远比训练时复杂的攻击，成功率也降到 <10%，而效用与防御前的模型相近。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 把防御从输入过滤搬到权重里，方法是将其转化为一个偏好学习问题：为同一份被污染的输入配对安全与不安全的补全，让模型学会偏好安全的那一个。
- **一句话卖点（Pitch）：** 在成对的安全/不安全输出上做偏好优化，把注入成功率压到 10% 以下，而效用基本不受影响。

### 4. StruQ: Defending Against Prompt Injection with Structured Queries (USENIX Security 2024)
- **问题（Problem）：** 提示注入之所以奏效，是因为 LLM 会遵循出现在任何位置的指令，并且无法把提示与用户数据分开。
- **假设（Assumption）：** 指令与数据的分离可以作为模型的一种学到的属性，而不只是前端强制的格式化约定。
- **机制（Mechanism）：** 结构化查询（structured queries）——一个安全前端把提示和数据格式化为两条独立通道，再加上一个微调过的 LLM：在指令微调数据集中注入放在数据部分的指令，模型学会忽略它们。
- **证据（Evidence）：** 实证评估显示对提示注入的抵抗力显著提高，而效用几乎没有或完全没有影响；摘要未给出数字。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 不要依赖输入通道来强制边界——把混淆的情形合成进训练数据（即必须被忽略的模式），让边界在模型内部得到强制。
- **一句话卖点（Pitch）：** 给提示和数据两条通道，并训练模型只服从提示通道。

### 5. WebInject: Prompt Injection Attack to Web Agents (arXiv 2025)
- **问题（Problem）：** 基于 MLLM 的 Web 智能体从网页截图生成动作，因此任何改变渲染像素的东西都能操纵智能体的行为。
- **假设（Assumption）：** 对原始像素值的扰动能够穿过“渲染到截图”的映射，并在该映射之后仍然有效，而这个映射可以被一个学习到的网络足够好地近似。
- **机制（Mechanism）：** 把扰动表述为一个优化问题；训练一个神经网络来近似不可微的“原始像素到截图”映射，然后用投影梯度下降求解重新表述后的问题。
- **证据（Evidence）：** 在多个数据集上的基准评估；被描述为高度有效并显著优于基线，摘要中没有数字。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 当你的可控输入与模型观测之间那一步不可微时，为那一步学习一个可微的替代模型（surrogate），并穿过该替代模型反向传播。
- **一句话卖点（Pitch）：** 扰动网页的原始像素，生成的截图就让 Web 智能体执行攻击者想要的动作。

### 6. UniGuardian: A Unified Defense for Detecting Prompt Injection, Backdoor Attacks and Adversarial Attacks in Large Language Models (arXiv 2025)
- **问题（Problem）：** 注入、后门和对抗攻击被分门别类地研究，而在攻击类型未知时，没有哪种防御能判断是否有隐藏触发器在操纵模型。
- **假设（Assumption）：** 成功的触发器激活会留下共同的特征——当提示被结构性扰动时，模型输出分布出现可测量的位移——这一特征为三类攻击家族所共有。
- **机制（Mechanism）：** 一个基于该共同机制的无训练检测器，外加一种单次前向策略，在每个解码步把检测与文本生成放在一次批量前向中一起完成。
- **证据（Evidence）：** 实验证实能够准确、高效地识别被触发器激活的提示；摘要未给出定量数字。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 通过扰动响应来检测，而不是对输入分类：施加小的结构性扰动并读取输出分布移动了多远，这一信号在攻击家族不同时依然有效。
- **一句话卖点（Pitch）：** 一个无需训练的问题——扰动是否移动了输出分布？——就能同时抓住注入、后门和对抗触发器。

### 7. Beyond Instruction Override: Benchmarking Indirect Prompt Injection with Task-Tampering Attacks (arXiv 2026)
- **问题（Problem）：** 现有的间接提示注入基准只测试替换任务的植入指令，而对篡改正在进行的任务结果的攻击既未测试也未检测。
- **假设（Assumption）：** 攻击性可以由权限来定义——当植入内容试图影响一个其来源无权决定的决策时，它就是攻击——而不是由类似指令的措辞来定义。
- **机制（Mechanism）：** 一个基准，涵盖三种工具使用环境中的 90 个经过验证的案例，每个案例的用户请求都点名了权威来源，并且每个案例都带有针对至多六个决策部分的攻击：目标、决策规则、可用动作、预期后果、观测解读和状态信念。
- **证据（Evidence）：** 对五个 LLM 的测量：无防御时，针对决策规则、可用动作和状态的攻击胜过针对目标的攻击；一种检测并移除的防御把目标攻击降到 2.4%，但观测和状态仍分别为 9.5% 和 12.1%；一种工具策略防御仍允许 15.4%（无防御时为 17.0%），因为这些攻击通常 re（摘要被截断）。
- **边界（Boundary）：** 摘要本身承认，检测并移除后，针对观测和状态的攻击仍分别有 9.5% 和 12.1%（在针对检测优化的改写下这一差距依然存在），而工具策略防御仍允许 15.4%。
- **可偷的一招（Stealable move）：** 按对某个决策的授权来定义威胁而不是按语法，然后枚举智能体的各项决策成分并逐一攻击——应当由最弱的那个成分、而不是最显眼的目标来设定基准。
- **一句话卖点（Pitch）：** 大多数间接注入并不重定向任务，而是篡改任务内部的一个决策，而当前的防御恰恰漏掉了这些。

### 8. Backdoor-Powered Prompt Injection Attacks Nullify Defense Methods (arXiv 2025)
- **问题（Problem）：** 指令层级（instruction hierarchy）等微调防御假设训练阶段是干净的，但污染微调数据的攻击者可以植入一个把防御关掉的触发器。
- **假设（Assumption）：** 攻击者可以污染监督微调（SFT）样本，并且植入的后门能在防御本身所用的那次微调中存活。
- **机制（Mechanism）：** 污染 SFT 样本以植入后门；触发器一旦激活，被植入后门的模型就执行包裹在触发器中的注入指令；并构建一个基准用于系统评估。
- **证据（Evidence）：** 基于基准的评估；报告称比以往的提示注入攻击危害更大，并能令包括指令层级在内的现有防御失效，摘要中没有数字。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 在与防御自身训练管线同处上游的位置放置对手来评估防御——把防御的训练数据视为攻击面的一部分，而不是可信输入。
- **一句话卖点（Pitch）：** 微调数据里的一个后门，就让提示注入防御、甚至指令层级，都停止工作。

### 9. LongPIBench: A Long-Context Benchmark for Prompt Injection (arXiv 2026)
- **问题（Problem）：** 现有的提示注入基准使用短上下文，因此防御是在与真实部署不同的情形下评估的，其有效性被大幅高估。
- **假设（Assumption）：** 攻击成功率和防御行为随上下文长度变化，而四种真实应用（同行评审、简历筛选、代码评审、邮件摘要）代表了重要的长上下文部署。
- **机制（Mechanism）：** 一个长上下文基准，包含四个真实场景，每个场景都同时有合成数据集和真实数据集，上下文从数千到数万 token。
- **证据（Evidence）：** 基准加测量；即便是简单的启发式攻击也能取得高成功率，并经常绕过最先进的防御；摘要未给出数字。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 在贴近部署的分布上，把防御有效性报告为输入长度的函数，因为在短长度上得到的结果只是防御真实质量的上界。
- **一句话卖点（Pitch）：** 在长上下文中，朴素的启发式注入就能穿透最先进的防御。

### 10. Maatphor: Automated Variant Analysis for Prompt Injection Attacks (arXiv 2023)
- **问题（Problem）：** 防御者针对他们发现的某一种注入技术打补丁，但这种注入的变体会绕过补丁，就像恶意软件变体绕过杀毒软件。
- **假设（Assumption）：** 变体可以被自动生成，而某个变体是否成功仅凭模型输出就能判定——一个黑盒预言机（oracle），无需接触内部。
- **机制（Mechanism）：** 一个工具，自动生成给定提示的变体，并自动从输出判断每个变体是否有效，同时为越狱和注入研究产出数据集。
- **证据（Evidence）：** 在三种不同类型的提示注入任务上评估；从一个无效（0%）的种子提示出发，它在前 40 次迭代内稳定生成有效性至少 60% 的变体。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 把一次已知失败转化为一个带黑盒成功预言机的自动变体生成器，这样防御就是对着一整个搜索过程评分，而不是对着一个固定产物。
- **一句话卖点（Pitch）：** 用自动生成的变体来测试防御，而不只是对着别人碰巧发现的那一种注入。

### 11. Latent Jailbreak: A Benchmark for Evaluating Text Safety and Output Robustness of Large Language Models (arXiv 2023)
- **问题（Problem）：** 基准只衡量越狱安全性，而对某些话题过度敏感会削弱模型遵循指令的能力，这一健壮性代价没有被测量。
- **假设（Assumption）：** 把恶意指令嵌入合法任务（如翻译）中是一种现实的越狱通道，并且安全性与指令健壮性在同一批提示上此消彼长。
- **机制（Mechanism）：** 一个潜在越狱（latent jailbreak）提示数据集，其中模型被要求对本身含有恶意指令的文本完成一项常规任务；外加一个分层标注框架，从指令位置、词语替换和指令替换等方面进行分析。
- **证据（Evidence）：** 基准加跨 LLM 的系统分析；发现模型会优先处理某些指令动词，且越狱率因动词而异；摘要未给出定量比率（摘要被截断）。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 在同一批提示上同时给安全性和任务遵循打分并报告两个轴，这样过度调校的拒答会显现为可见的健壮性代价，而不是隐藏的安全收益。
- **一句话卖点（Pitch）：** 安全性与健壮性必须一起做基准，因为推动其中一个会移动另一个。

### 12. Gradient Cuff: Detecting Jailbreak Attacks on Large Language Models by Exploring Refusal Loss Landscapes (NeurIPS 2024)
- **问题（Problem）：** 经 RLHF 对齐的 LLM 仍会被对抗性越狱攻破，需要一个能把越狱查询与良性查询区分开的检测器。
- **假设（Assumption）：** 越狱位于模型拒绝损失景观（refusal-loss landscape）中可区分的一片区域——损失值及其平滑性都与良性查询不同。
- **机制（Mechanism）：** 定义拒绝损失（Refusal Loss），然后是一个两步检测策略，使用其函数值以及在扰动下的平滑性，阈值可调。
- **证据（Evidence）：** 在两个对齐 LLM（LLaMA-2-7B-Chat、Vicuna-7B-V1.5）和六种越狱类型（GCG、AutoDAN、PAIR、TAP、Base64、LRL）上的实证评估；提高了拒绝率，并通过调整检测阈值保持良性性能。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 用模型自身损失景观的几何——值加上扰动下的平滑性——作为检测特征；它继承自对齐过程，因此能泛化到文本上毫无共同点的不同攻击家族。
- **一句话卖点（Pitch）：** 越狱在拒绝损失景观中留下指纹，一个查值和查平滑性的两步检查就能找到它。

### 13. Jailbreak Distillation: Renewable Safety Benchmarking (arXiv 2025)
- **问题（Problem）：** 安全基准会饱和并受到污染，固定的提示集跟不上模型的代际更新。
- **假设（Assumption）：** 一小组开发模型结合现有攻击算法可产生一个候选池，从中选出的子集能预测那些未参与构建的模型的安全表现。
- **机制（Mechanism）：** JBDistill——从开发模型和越狱算法构建候选提示池，然后运行提示选择算法挑出有效子集作为基准；重新运行该管线即可刷新。
- **证据（Evidence）：** 基准构建加评估；泛化到 13 个留出的评估模型（专有、专用、更新一代），在有效性上优于现有安全基准，同时保持高可分离性和多样性。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 把基准作为“生成器 + 选择过程”交付，而不是一份冻结的清单，这样饱和与污染靠重跑构建来处理，而不是靠手工撰写新条目。
- **一句话卖点（Pitch）：** 把实时的越狱攻击提炼成一小份提示集，它在没见过的模型上依然有效，且刷新成本很低。

### 14. JailbreakBench: An Open Robustness Benchmark for Jailbreaking Large Language Models (NeurIPS 2024)
- **问题（Problem）：** 越狱评估没有标准做法，算出的成本和成功率不可比，而且常常无法复现，原因包括不公开提示、不开放代码或不断变化的专有 API。
- **假设（Assumption）：** 把整个测量栈固定下来——威胁模型、系统提示、对话模板、评分函数——连同开放的产物，能让攻击与防御的结果可比且可复现。
- **机制（Mechanism）：** 一个开源的基准，结合一个不断演进的对抗提示库（越狱产物）、一个 100 行为数据集、一个标准化评估框架，以及一个公开排行榜。
- **证据（Evidence）：** 基准产物：100 个行为，原创或取自先前工作（Zou et al., 2023; Mazeika et al., 2023, 2024），与 OpenAI 的使用政策一致；排行榜追踪跨 LLM 的攻击与防御。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 把测量装置作为成果的一部分发布——把威胁模型、系统提示、对话模板和评分器与数据一起钉死，因为在对抗性评估中，测量栈会改变数字。
- **一句话卖点（Pitch）：** 一个提示、模板和评分都固定的共享开放测量装置，才是让越狱数字可比的东西。

### 15. LLMs Can Defend Themselves Against Jailbreaking in a Practical Manner: A Vision Paper (arXiv 2024)
- **问题（Problem）：** 越狱攻击（GCG、DAN 模板、多语言）不断进步，而防御——还必须对良性流量保持快速——落在了后面。
- **假设（Assumption）：** 无论越狱策略为何，有害提示本身最终必须出现在发给模型的文本中，而当前的 LLM 已经能够识别这类违反政策的提示。
- **机制（Mechanism）：** SELFDEFEND——一个影子栈，并发检查用户输入中是否有有害提示，并在正常栈输出 “No” token 或有害提示时触发检查点，同时给出可解释的响应。
- **证据（Evidence）：** 愿景论文；在 GPT-3.5/4 上对各种越狱场景做人工分析，并列出三个未来方向；没有定量数字。
- **边界（Boundary）：** 摘要承认其支撑是 GPT-3.5/4 上的人工分析，并且还有三个未来方向有待加强该设计。
- **可偷的一招（Stealable move）：** 找出一个攻击家族中每个成员都必须满足的不变量，只检查那一件事，并在并行的影子执行中完成——既不枚举攻击，对良性流量也几乎不花代价。
- **一句话卖点（Pitch）：** 每次越狱最终都必须说出有害请求，所以一个并发的影子检查就能以可忽略的延迟抓住它。

### 16. TombRaider: Entering the Vault of History to Jailbreak Large Language Models (arXiv 2025)
- **问题（Problem）：** 聊天机器人安全过滤器需要被新的通道绕过，红队工作需要不是已知模板明显改写的越狱技术。
- **假设（Assumption）：** 模型存储的历史知识可以被检索并加以框定，使有害内容以历史叙事而非请求的形式出现，从而规避过滤器。
- **机制（Mechanism）：** 两个协作的智能体——一个检查员智能体提取相关历史信息，一个攻击者智能体据此生成对抗提示。
- **证据（Evidence）：** 在六个流行模型上的实证评估；裸模型上 ASR 接近 100%，对防御机制 ASR 超过 55.4%。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 把攻击拆成侦察角色与组合角色，侦察角色取回无害的片段，组合角色把它们组装起来，这样有害载荷从不在任何单一位置被写出来，过滤器看不到它。
- **一句话卖点（Pitch）：** 从模型自身知识中取出的历史叙事，是一条当前保障措施尚未覆盖的越狱通道。

### 17. EnJa: Ensemble Jailbreak on Large Language Models (arXiv 2024)
- **问题（Problem）：** 对齐的 LLM 仍会输出违反政策的内容；提示级越狱（故事/逻辑）和 token 级梯度攻击各自都有天花板。
- **假设（Assumption）：** 这两个家族足够互补，把它们组合起来能保留各自的长处，而不是被平均掉。
- **机制（Mechanism）：** 集成越狱（Ensemble Jailbreak）——用提示级越狱隐藏有害指令，用基于梯度的 token 级攻击提升攻击成功率，并用一个基于模板的连接器把两者接起来。
- **证据（Evidence）：** 在若干对齐模型上的实证评估；以更少的查询达到最先进的攻击成功率，并远强于任何单一越狱；摘要中没有数字。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 组合作用于不同粒度的攻击原语并用固定模板把它们粘起来——通常胜过放大任何单一原语，而且查询更少。
- **一句话卖点（Pitch）：** 在 token 级优化器下面叠一层提示级伪装，这个混合体以更少的查询胜过任一单一攻击。

### 18. Jailbreaking Attack against Multimodal Large Language Model (arXiv 2024)
- **问题（Problem）：** MLLM 可被驱使对有害查询生成令人反感的回答；越狱必须能跨未见的提示和图像奏效，最好还能迁移到其他模型。
- **假设（Assumption）：** 通过最大似然找到的单个图像空间越狱提示具有数据通用性，并能以黑盒方式跨模型架构迁移。
- **机制（Mechanism）：** 一个基于最大似然的算法，找到一个图像越狱提示（imgJP）；另有一种基于构造的方法，利用所发现的 MLLM 与 LLM 越狱之间的联系，复用该方法来构建 LLM 越狱。
- **证据（Evidence）：** 以黑盒方式在 MiniGPT-v2、LLaVA、InstructBLIP 和 mPLUG-Owl2 上的迁移评估；对于 LLM 越狱，它比当前最先进方法更高效；摘要中没有数字。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 付一次搜索成本，在一种模态中找到一个通用产物，然后通过一条构造规则把它带到另一种模态，而不是从头重新优化。
- **一句话卖点（Pitch）：** 一个由最大似然优化的图像越狱提示，迁移到未见的输入、未见的图像和黑盒模型。

### 19. Foot In The Door: Understanding Large Language Model Jailbreaking via Cognitive Psychology (arXiv 2024)
- **问题（Problem）：** 越狱工作报告成功率，但对 LLM 收到越狱提示后的内部决策过程不作解释。
- **假设（Assumption）：** 认知一致性理论可以迁移到 LLM——一旦模型以小的步骤对某个立场做出承诺，它就会通过继续而不是拒绝来解决不一致。
- **机制（Mechanism）：** 一种自动的黑盒“得寸进尺”（Foot-in-the-Door, FITD）方法，通过多步渐进提示逐步诱导模型回答有害问题；实现为一个原型系统。
- **证据（Evidence）：** 在 8 个先进 LLM 上的原型评估，平均成功率 83.9%。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 用一串各自无害的承诺阶梯替换单一的、决定性的对抗输入，这样拒绝下一步就与模型已经说过的话不一致。
- **一句话卖点（Pitch）：** 越狱是一个认知一致性问题：小步升级，模型就会自己说服自己顺从。

### 20. Jailbreaking Large Language Models with Morality Attacks (arXiv 2026)
- **问题（Problem）：** 多元主义对齐（pluralism alignment）正在被追求，但 LLM 和护栏模型在跨越多元价值产生道德内容时的健壮性如何，仍未被探索。
- **假设（Assumption）：** 模糊或有冲突的道德问题会暴露内在价值，而越狱式提示能足够可靠地操纵这一判断，从而可被测量。
- **机制（Mechanism）：** 一个包含 10.3K 个实例的道德数据集，分两类：价值模糊（Value Ambiguity）和价值冲突（Value Conflict）；外加四种形式化的对抗攻击，用来操纵模型在这些问题上的判断，并对 LLM 和护栏模型都进行评估。
- **证据（Evidence）：** 数据集加评估；10.3K 个实例；结果表明 LLM 和护栏模型都对这类微妙的道德感知攻击存在严重脆弱性，未给出比率。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 把攻击机器重新用作测量工具——用对抗提示探测模型内部偏好什么，而不是攻破它，从而把一个价值问题变成实证问题。
- **一句话卖点（Pitch）：** 微妙的道德感知越狱暴露出 LLM 与护栏的多元判断有多么脆弱。

### 21. Off-Path TCP Hijacking in Wi-Fi Networks: A Packet-Size Side Channel Attack (arXiv 2024)
- **问题（Problem）：** Wi-Fi 网络中的路径外（off-path）攻击者看不到受害者的连接状态，而这正是 TCP 劫持所需，尽管 WEP 与 WPA2/WPA3 保护了载荷。
- **假设（Assumption）：** 加密帧的大小对每种响应类型都是稳定且可区分的，因此仅凭帧大小就足以泄露推断序列号并注入所需的状态。
- **机制（Mechanism）：** 利用可观测的帧大小侧信道——TCP 接收方的 ACK 与 RST 响应大小不同，承载它们的加密帧有稳定且可区分的大小——来检测并劫持连接，并以 SSH DoS 和 Web 流量操纵加以展示。
- **证据（Evidence）：** 真实部署加测量：SSH 会话在 19 秒内被终止，恶意数据在 28 秒内被注入 Web 流量；来自 9 个厂商的 30 款流行路由器，无一具备防护；测试了 80 个真实 Wi-Fi 网络，其中 75 个（93.75%）劫持成功；向 Wi-Fi Alliance 做了负责任披露并提出缓解策略（摘要被截断）。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 当内容被加密时，转而攻击长度——消息大小往往仍足以对消息类型分类，从而在不解密任何东西的情况下重建协议状态。
- **一句话卖点（Pitch）：** 加密的 Wi-Fi 帧大小泄露了足够的 TCP 状态，让路径外攻击者在 93.75% 的受测真实网络中劫持连接。

### 22. A Practical Deep Learning-Based Acoustic Side Channel Attack on Keyboards (S&P 2023)
- **问题（Problem）：** 声学键盘侧信道早已为人所知但并不实用；无处不在的麦克风和更好的分类器改变了威胁等级。
- **假设（Assumption）：** 由现成智能手机麦克风或视频会议通话采集的按键声学信号，无需任何语言模型即可由深度学习分类器区分。
- **机制（Mechanism）：** 训练一个最先进的深度学习模型，对由附近智能手机麦克风录制的笔记本按键进行分类，另单独通过视频会议软件 Zoom 进行。
- **证据（Evidence）：** 真实测量：在由附近手机录制的按键上训练时准确率 95%，是未使用语言模型时见过的最高准确率；通过 Zoom 为 93%，是该媒介的新最好成绩。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 用消费级硬件和现代分类器重跑一个已知的实验室侧信道；展示现成条件下的实用性本身就是贡献，并且它改变了威胁模型的假设。
- **一句话卖点（Pitch）：** 一个智能手机麦克风加一个深度分类器，就能以 95% 的准确率还原笔记本按键，不需要专用设备。

### 23. Beyond the Bridge: Contention-Based Covert and Side Channel Attacks on Multi-GPU Interconnect (arXiv 2024)
- **问题（Problem）：** NVLink 等高速互连由多 GPU 系统的所有租户共享，但其拥塞尚未被当作泄露通道对待。
- **假设（Assumption）：** 没有特殊权限的对手能以足够的分辨率观测互连拥塞，从而把受害者的活动与噪声区分开。
- **机制（Mechanism）：** 在没有特殊权限的情况下监视 NVLink 拥塞，用该信号在两个 GPU 之间构建隐蔽信道，并构建一个能对受害者应用做指纹识别的侧信道。
- **证据（Evidence）：** 真实系统测量：跨两个 GPU 的隐蔽信道具 45.5 kbps 带宽且错误率低；侧信道可通过共享互连对应用做指纹识别。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 把任何共享的高带宽互连——不只是缓存——都当作时序信道；一个无特权租户的争用测量就足以同时得到隐蔽信道和应用指纹。
- **一句话卖点（Pitch）：** 无需特权即可看见的 NVLink 拥塞，带来一条 45.5 kbps 的隐蔽信道，并让攻击者能对应用做指纹识别。

### 24. PREFENDER: A Prefetching Defender against Cache Side Channel Attacks as A Pretender (arXiv 2023)
- **问题（Problem）：** 缓存侧信道攻击（一般型与瞬态执行型）已有对策，但它们大多以性能换安全，或覆盖面有限。
- **假设（Assumption）：** 攻击者本身必须触碰缓存以操纵状态并观察变化，所以攻击者的访问模式是可预测的，因而可以被抢先。
- **机制（Mechanism）：** 一个安全的预取器，学习并预测与攻击相关的访问，并预取那些缓存行，用一种机制同时服务安全与性能。
- **证据（Evidence）：** 模拟/基准评估：对若干缓存侧信道攻击有效，同时在 SPEC CPU 2006 和 2017 上保持甚至提升性能。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 不要去阻断对手的观测，而是预先提供它想测量的状态，使观测变得毫无价值——这样防御与性能优化就成了同一个机制。
- **一句话卖点（Pitch）：** 一个能预测攻击者访问的预取器，既防御缓存侧信道，又同时提升性能。

### 25. Timing the Transient Execution: A New Side-Channel Attack on Intel CPUs (arXiv 2023)
- **问题（Problem）：** 瞬态执行攻击需要一个隐蔽信道来泄露数据，常用信道依赖缓存，而缓存正日益被缓解且可被检测。
- **假设（Assumption）：** 瞬态执行期间对 EFLAGS 的改动会对后续 Jcc 指令产生副作用，由此产生的时序差异足以编码比特，而无需手动重置 EFLAGS。
- **机制（Mechanism）：** 把秘密数据编码进令上下文执行稍慢的寄存器变化中，然后测量瞬态执行与 Jcc 指令的时序来解码数据；并与 Meltdown 结合作为其侧信道。
- **证据（Evidence）：** 真实硬件：在 Intel Core i7-6700、i7-7700 和 i9-10980XE 上实现；在前两者上，与 Meltdown 结合后达到 100% 的泄露成功率。
- **边界（Boundary）：** 摘要未说明
- **可偷的一招（Stealable move）：** 当显而易见的信道（缓存）被加固时，去寻找在上下文之间未被显式重置的微架构状态——任何作为副作用留存下来的东西仍然是信道。
- **一句话卖点（Pitch）：** 瞬态执行期间的 EFLAGS 变化通过 Jcc 时序泄露，给出一条不需要缓存的侧信道。
