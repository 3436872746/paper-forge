# 会议门槛 — 安全（50 篇论文，2023–2026）

本文件让从事这一方向的人把自己的草稿或实验计划与本语料库中 50 篇论文的实际做法对照，并在审稿人替你做之前先自查。
它仅从摘要推导而来，因此下文每一条主张都是关于某份摘要说了什么的主张，而不是关于论文做了什么的主张。
卡片引用沿用 `(cards 1-7, 2-13)` 的约定：批次-卡片，因此 `1-7` 是 `cards_batch1.md` 的第 7 张卡，`2-13` 是 `cards_batch2.md` 的第 13 张卡。

## 1. 这些论文实际研究什么

- **控制检索内容或外部内容的攻击者能否覆盖应用的指令，模型能否被训练成把该内容当作数据而非指令？** 这是本语料库 LLM 那一半的主导问题，从攻击侧与训练期防御侧都被提出 `(cards 1-1, 1-3, 1-4, 1-5, 1-8)`。
- **防御能否在已经知道它的攻击者面前存活？** 指令层级防御对着被后门化的微调数据评估，而在某一攻击家族上调校的防御则对着自动生成的变体运行 `(cards 1-8, 1-10, 1-3)`。
- **哪条通道能让对齐模型输出违反政策的答案，该通道能迁移多远？** 模板、梯度、图像、多轮升级、检索到的历史叙事和道德框定都被各自提出为一条独立通道，并各自在多个模型上打分 `(cards 1-16, 1-17, 1-18, 1-19, 1-20)`。
- **一个廉价、模型内部的信号能否足够好地区分攻击与良性输入，从而可以用阈值把关？** 在整理语料上训练的分类器、拒绝损失几何和扰动响应检测器是现有的三种变体 `(cards 1-2, 1-6, 1-12)`。
- **当输入分布改变时，现有基准与防御是否仍然成立？** 更长的上下文、篡改任务内部某个决策而非替换任务的攻击，以及基准饱和，都被用来表明防御报告的数字是测试集的产物 `(cards 1-7, 1-9, 1-13)`。
- **哪个无特权的可观测量足以泄露并重建秘密或协议状态？** 缓存行为、EFLAGS/Jcc 时序、NVLink 拥塞、AMX 延迟和加密帧大小都被各自视为足够 `(cards 1-23, 1-25, 2-3, 1-21)`。
- **一个已知侧信道在消费级硬件和现实噪声下是否实用？** 贡献在于重跑而不是通道本身：智能手机麦克风、一次 Zoom 通话，以及用户自己的打字节奏 `(cards 1-22, 2-2, 2-4)`。
- **构建、打包或模块管线中的哪一道接缝让攻击者无需触碰受害者代码即可行动，什么性质能封住它？** 打包顺序、依赖解析、模块接口，以及运行时的工具/上下文来源是接缝；透明性、有效性、分离性和来源（provenance）是所提出的封堵 `(cards 2-16, 2-18, 2-17, 2-25, 2-24)`。

一条并行的线索——模糊测试、静态分析和修复——问的是如何让输入越过解析器和协议层抵达深层代码，以及如何知道一次崩溃确实证实了漏洞，而不是一次静态匹配 `(cards 2-6, 2-9, 2-10, 2-15, 2-14)`。

## 3. 隐含的检查清单

1. **把攻击者的能力陈述为读者可以证伪的一句话**——他们能写、读、执行、计时或观测什么，以及不能做什么。这一方向的审稿人需要先知道边界，才能判断你的结果在你的设置之外是否有意义——`(cards 1-7, 1-21, 2-3, 1-14)`——若缺失，可能的反对意见是“我无法判断这个攻击者是否存在于我的部署中，所以我无法使用这个结果”。
2. **对着针对你优化过的、或从你的开发集中留出的攻击者做评估**——一个只在调校时所用攻击上打分的防御，衡量的是你的调校，而不是你的防御——`(cards 1-3, 1-7, 1-10, 1-1)`——若缺失：“评估集就是训练集换了标点”。
3. **报告良性输入上的代价，而不只是攻击成功率**——没有误报数字的检测器不可部署，而本领域已经吃过那种唯一陈述的代价是“可忽略”的防御的亏——`(cards 1-3, 1-4, 1-12, 1-11)`——若缺失：“我的合法流量会怎样？”
4. **至少在两个模型家族或系统上评估，或解释为什么一个是代表性的**——迁移性与通用性正是这一文献最常主张、也最少支撑的两件事——`(cards 1-12, 1-13, 1-16, 1-19, 2-15)`——若缺失：“单模型结果；我预计换到下一个检查点就会变”。
5. **与一个具名的基线防御比较，而不只是与无防御比较**——打赢无防御的模型不是贡献；打赢显而易见的现有防御才是——`(cards 1-7, 1-8, 1-9, 2-18)`——若缺失：“这比栈里已有的防御好在哪里？”
6. **陈述使防御可用的部署假设**——上下文长度、它在栈中的位置、它需要看到什么、它消耗多少延迟预算，以及它是否需要模型权重——`(cards 1-14, 1-15, 1-21, 2-19)`——若缺失：“这是在与任何部署都不同的制度下评估的，所以该数字是一个上界”。
7. **用运营者实际支付的单位报告你施加的运营代价**——每请求毫秒数、内存、页面加载时间或 GPU 时间，在普通流量上测量，而不只是在攻击上——`(cards 1-15, 1-24, 2-19)`——若缺失：“没有开销数字，所以我假定它高得无法承受”。
8. **按你所遗漏的组件的粒度，报告你的方法未覆盖什么**——这里最强的论文会点名仍然漏过的子情形并给出其比率——`(cards 1-7, 1-9, 1-12)`——若缺失：“评估针对的是容易的组件；弱的那个没被测试”。
9. **把测量栈与结果分开**——系统提示、对话模板、评分器、裁判模型、查询预算和解码设置都属于论文正文，因为在对抗性评估中测量装置会改变数字——`(cards 1-14, 1-13, 1-9)`——若缺失：“你的比率是你测量装置的性质，不会复现”。
10. **给每个比率一个基数**——N 个案例、N 次查询、N 次尝试、N 秒、N 次迭代；没有分母的百分比无法与本语料库中的任何东西比较——`(cards 1-10, 1-16, 1-19, 1-21)`——若缺失：“83.9% 是什么的 83.9%？”
11. **测试你声称的输入分布，而不是方便的那个**——长上下文、分层协议格式、现实噪声、真实用户行为；这里有几篇论文之所以存在，正是因为短的干净版本高估了防御——`(cards 1-9, 2-6, 2-4)`——若缺失：“评估条件正是你的方法为之设计的那些条件”。
12. **通过执行确认漏洞或修复，而不是通过相似度或静态匹配**——一个匹配到的易受攻击函数不是一个可触发的缺陷，一个与参考补丁相似的补丁也不是修复——`(cards 2-10, 2-15, 2-14, 2-6)`——若缺失：“你的命中率其实是伪装的误报率”。
13. **在发布漏洞利用之前披露一个在用的漏洞**——本语料库中唯一一张攻破已部署协议的卡片，写明了通知了谁、提出了什么缓解；审稿人会问——`(cards 1-21)`——若缺失：“有没有联系任何厂商，时间线如何？”
14. **发布产物，或精确说明读者重建它需要什么**——代码、提示、数据、测量装置；在无法发布时，说明扣留了什么以及为什么——`(cards 1-3, 1-4, 1-11, 1-14)`——若缺失：“不可复现，而在这类文献中这通常意味着不可比”。
15. **区分“我们发现了一个漏洞”与“我们能发现这一类漏洞”**——单个演示案例是案例研究，摘要应如实说明而不是泛化——`(cards 2-7, 2-6, 1-10)`——若缺失：“一个实例，被当作一种方法来呈现”。

## 4. 这一方向的审稿人会问的十个问题

1. **“你的攻击者究竟能做什么，不能做什么？”**——好的回答是一句能力陈述加一句排除项，放在第一个结果之前。
2. **“这个防御是在你测试它的那些攻击上开发出来的吗？”**——好的回答说出一开始留出或优化过的攻击者，并把其上的数字与开发集分开报告。
3. **“这在我的合法流量上代价如何？”**——好的回答给出带分母的误报或效用数字，加上工作阈值处的延迟。
4. **“为什么是这些模型，换到下一个版本还成立吗？”**——好的回答至少给出两个家族，并说明哪个结果是架构特定的。
5. **“基线是什么，为什么是它？”**——好的回答是一个由你在自己的输入上运行的具名现有防御，而不是从其论文中引用的数字。
6. **“这在真实系统中位于何处，要它运行需要什么成立？”**——好的回答是文字形式的部署图：输入路径、信任边界、延迟预算，以及该组件不可用时的失效模式。
7. **“你的威胁中哪一部分没有被处理？”**——好的回答点名未覆盖的组件并给出其测得的成功率，而不是把它说成未来工作。
8. **“你的数字是攻击的性质还是你的评估测量装置的性质？”**——好的回答钉死提示、模板、评分器和查询预算，并至少在一种测量装置扰动下展示该数字。
9. **“我能根据你写的东西复现它吗？”**——好的回答是已发布的产物，或一份明确列出扣留内容与获取条件的清单。
10. **“你的方法失败之后，有什么东西仍然成立？”**——好的回答是机制层面的陈述——哪条通道、哪个可观测量、哪项设计性质——即使具体防御被攻破也仍然为真。

## 6. 不要照抄什么

- **把固定攻击集当作整个评估。** 大多数检测与防御卡片是在取自先前工作的具名攻击集上打分的，没有会对防御做出反应的攻击者。这是本语料库中最常见的单一弱点（只有 11/50 报告了任何自适应结果），而报告了自适应结果的论文，正是改变防御评判方式的那几篇 `(cards 1-1, 1-3, 1-7, 1-10)`。
- **只报告攻击成功率的防御。** 五十份摘要中有六份给出了良性侧数字。报告“ASR 降到 X% 以下”却没有误报率、没有延迟、没有陈述阈值，会让审稿人去假设你的工作点最坏的情况 `(cards 1-3, 1-4, 1-12)`。
- **威胁模型只是一个攻击家族的名字。** “我们防御提示注入”陈述的是一个场景，而不是一种能力。把攻击者写清楚的卡片，也正是读者能拿自己场景去核对的卡片 `(cards 1-21, 2-3, 1-7)`。
- **把干净条件下的数字当作部署数字呈现。** 本语料库中有几篇论文之所以存在，正是因为早先的干净条件数字高估了结果；短上下文、实验室声学环境和合成输入格式都在美化方法。如果你的评估条件就是你的设计条件，请说明 `(cards 1-9, 2-4, 2-6)`。
- **把单次演示写成一种方法。** 一个易受攻击的应用、一个目标二进制或一个 CVE 就是案例研究。本语料库中诚实的卡片会把它标为初步，并把大规模评估放进计划里 `(cards 2-7, 2-16, 2-6)`。
