# 会议门槛 — LLM 推理调度（50 篇论文，2023–2026）

这份文件是给任何在 LLM 推理调度方向写作或规划工作的人准备的对照门槛：拿你的草稿与实验计划，去对照这 50 篇论文实际做了什么。
它只从摘要（以及由摘要构建的想法卡片）推导而来——此处没有任何内容来自全文，因此"摘要未说明"就是字面意思。
卡片引用使用约定 `(cards 1-7, 2-13)`：第一个数字 = 批次，第二个 = 该批次中的卡片编号；1-1 … 1-25 与 2-1 … 2-25 即这 50 篇论文。
语料说明：检索窗口为 2023–2026，但选出的 50 篇论文日期为 2024–2026（7 / 12 / 31）；没有 2023 年的论文通过筛选。

## 1. 这些论文实际研究什么

- **在作业规模未知时，谁被准入，按什么顺序。** 主导性问题是：在不了解输出长度的情况下如何取代 FCFS 批处理——用预测长度、剩余 token、KV 占用，或一个排队替代模型（cards 1-9, 1-11, 1-14, 1-16, 1-25, 2-22）。
- **KV 缓存容量作为硬约束，以及缓存放在哪里。** 并发由 KV 内存决定，因此论文要决定预留什么、保留什么、驱逐什么、迁移什么或卸载什么——并且，一旦复用值得保留，路由应当跟随缓存还是跟随闲置容量（cards 1-1, 1-2, 1-10, 1-18, 1-21, 1-24, 2-1, 2-14, 2-16, 2-22）。
- **Prefill–decode 干扰，以及如何消除它。** 分离、部分分离，以及在某一侧闲置时把工作移回跨越这两个阶段（cards 1-8, 1-17, 2-2, 2-9, 2-15, 2-20）。
- **尾延迟与 SLO 达成率，而不是平均延迟。** 头条数字通常是给定目标下的 SLO 达成率、goodput 或 p99，而不是平均延迟（cards 1-3, 1-8, 1-13, 1-17, 1-18, 2-4, 2-25）。
- **跨租户、优先级与请求类别的公平与隔离。** 均等的长期吞吐被认为不够；论文会加入延迟隔离、亏空计数器、按优先级加权的收益，或实时/尽力而为共享（cards 1-2, 1-6, 1-12, 1-22, 2-13）。
- **工作流级而非调用级的目标。** 请求是 DAG、agent 工作流、工具调用或查询计划，调度以工作流完成时间来评判（cards 1-5, 1-15, 1-17, 1-24, 2-3）。
- **能耗、成本与异构硬件作为目标。** 一些论文优化焦耳、碳或 GPU 小时而不是延迟，跨越混合 GPU 类型与内存层级（cards 1-3, 1-6, 1-19, 2-8, 2-15, 2-17, 2-19）。
- **工作负载本身，以及这个领域赖以运行的模拟器。** 一个可见的少数群体测量流量、发布轨迹，或构建别人用来评估的模拟器（cards 1-20, 2-6, 2-7, 2-11）。

## 3. 隐含的检查清单

1. **在一个并非你发明的工作负载上评估。** 这个方向的审稿人已经见过工作负载论文论证：结论会在现实的突发性与混合长度下翻转——`(cards 1-20, 2-6, 2-7)`——"若缺失：你的收益可能是一个均匀、类泊松流的产物；请展示轨迹，或说明你的为何有代表性。"
2. **陈述到达过程，以及负载有多突发。** 本语料惯常变动到达模式与并发，且有几篇论文把突发性当作解释变量——`(cards 1-11, 1-20, 2-7)`——"若缺失：论文从未定义它的负载，因此没人能复现或比较这个结果。"
3. **至少使用两个模型规模或两个模型家族。** 报告跨规模结果的卡片都测试了两种规模，而单设备卡片明确把论断限定在该设置内——`(cards 2-1, 2-15, 1-21, 2-7)`——"若缺失：单模型证据；机制却是在为泛化的服务做声称。"
4. **陈述硬件与 GPU 数量，并测试不止一种配置。** 本语料中有分量的结果都报告了显式的部署规模——`(cards 1-8, 1-10, 2-1, 2-15, 2-22)`——"若缺失：没有规模，审稿人无法判断该调度器在集群规模上是否还有帮助。"
5. **以运行在同一引擎上的最接近的先前系统为基线。** 这项工作的大部分是既有引擎上的增补，并与该引擎自己的调度器比较，而不只是与 FCFS 比较——`(cards 1-7, 1-16, 1-24, 2-22)`——"若缺失：FCFS 是稻草人；原生调度器早就做到了这件事。"
6. **报告尾部，而不只是均值。** 本语料中最锋利的论断都陈述在 p99 或类别条件尾延迟上，而不是平均值上——`(cards 1-1, 1-17, 1-24, 2-1, 2-25)`——"若缺失：机制可能正在用尾部换均值，而论文把它藏了起来。"
7. **在给定目标下报告 SLO 达成率或 goodput。** 没有目标的延迟数字无法跨系统比较——`(cards 1-3, 1-8, 1-10, 1-18, 2-15)`——"若缺失：我们无法判断是否守住了任何对用户可见的承诺。"
8. **报告资源侧：GPU 小时、实例数、美元或能耗。** 一个在更多机器上达成 SLO 的调度器是亏的——`(cards 1-3, 1-6, 1-10, 2-8, 2-15)`——"若缺失：你的延迟可能是用硬件买来的。"
9. **对机制做消融，展示去掉它收益就崩塌。** 此处没有任何摘要报告过消融（0/50），这正是该领域的机制声称难以被证伪的原因——这是击败本语料成本最低的地方——`(cards 1-3, 1-13, 1-24, 2-22)`——"若缺失：端到端数字可能来自三个协同设计部件中的任何一个。"
10. **陈述过载下的行为与回退路径。** 依赖预测、准入或迁移的策略，需要一个明确的答案来应对预测出错或队列已满——`(cards 1-11, 1-21, 2-19, 2-22)`——"若缺失：饱和时会发生什么，或预测误差非对称或很大时会发生什么，都被留给读者。"
11. **量化你所依赖的任何预测器的误差，并展示该误差下的策略表现。** 预测引导的排序，其好坏只取决于它的误差模型——`(cards 1-9, 1-11, 1-25, 2-5)`——"若缺失：预测器只在自己的训练分布上被评估过；请展示退化，而不只是准确率。"
12. **陈述收益消失的边界。** 陈述了边界的卡片，正是那些把声称限定在某个区间内的卡片——`(cards 1-7, 1-19, 1-21, 1-22, 2-7, 2-22)`——"若缺失：声称是无条件的，而审稿人会找出它失效的区间。"
13. **给出可复现细节：引擎版本、基准、代码、种子。** 只有在同一技术栈上运行，结果才可比较——`(cards 1-16, 1-19, 1-20, 1-25, 2-6, 2-11)`——"若缺失：这里的任何东西都无法在我们的集群上重跑。"
14. **解释基线为何强，并慷慨地配置它。** 相对调优过的系统取得的大倍数，会招来"基线是怎么调的"这一质疑——`(cards 1-2, 1-16, 1-24, 2-5, 2-22)`——"若缺失：基线只跑了默认值，或被剥夺了你的策略所获得的同等信息。"
15. **给出机制层面的论证，说明它为何胜出。** 一个证明、一个排队模型，或一份实测的延迟分解，正是把策略与配方区分开的东西——`(cards 1-11, 1-13, 1-14, 1-16)`——"若缺失：它就是一个工程配方，我们学不到它何时可迁移。"

## 4. 审稿人在这个方向会问的十个问题

1. **"这是什么工作负载，我为什么要相信它的到达与长度分布？"** 一个好答案：一条点名的轨迹或一个已发布的生成器、观测到的突发性与长度分布跨度，以及一句话说明被评估流量为何与被声称的部署相似。
2. **"这个胜出是相对你的消融，还是相对所有人真正在跑的系统？"** 一个好答案：两者都要——击败已部署引擎的原生调度器，以及在关掉你的机制后击败同一系统。
3. **"尾部去哪了？给我看 p99，不是均值。"** 一个好答案：同一次运行上的均值与 p99（或类别条件尾延迟），并把 SLO 线画出来。
4. **"在什么负载下你的策略不再有帮助？"** 一个好答案：带交叉点标记的负载扫描，以及超过饱和之后调度器会做什么。
5. **"预测错了会怎样？"** 一个好答案：实测的误差分布，加上策略在刻意非对称或放大的误差下的行为。
6. **"为什么这不是旧方法换了个名字？"** 一个好答案：精确指出不同的那个量，以及旧方法的假设失效的那个实验。
7. **"你花了多少块 GPU 才买到这个？"** 一个好答案：固定 SLO 下的 GPU 小时或实例数，而不只是以某种代价换来的延迟。
8. **"这能撑过第二个模型或第二个租户吗？"** 一个好答案：至少一个带同驻、干扰或竞争客户端类别的实验。
9. **"哪个组件承载了收益？"** 一个好答案：留一法（leave-one-out）消融，把每个协同设计部件的贡献分开。
10. **"你论断的边界是什么——哪些工作负载、哪些硬件、哪个 SLO？"** 一个好答案：一个显式的包络，包括机制中性或为负的区间。

## 6. 不该照抄的东西

- **把"最高 Nx"当作结果。** 许多摘要以最佳情形的倍数为头条，背后没有分布或中位数（cards 1-1, 1-5, 1-15, 2-19）；读者无法判断是典型请求改善了，还是只有幸运的那一个。
- **一个模型、一块 GPU。** 单模型与单设备证据出现在语料中（cards 1-21, 2-7），但只支撑一个狭窄的论断；照抄它会招来"这能撑过第二个模型吗"的质疑。
- **仅仿真或仅合成的评估。** 五张卡片仅依赖仿真或分析（cards 1-11, 1-14, 2-10, 2-11, 2-23），这对一个界是站得住的，但对关于真实调度器行为的论断不是。
- **说"state-of-the-art"却不点名系统。** 15/50 的摘要这么做（cards 1-3, 1-4, 2-8）；这使比较不可证伪，也是审稿人首先要追问的。
- **省略模型名，或省略消融。** 41/50 的摘要从未点名模型，0/50 描述消融；两者都是语料的缺口，而不是应当继承的标准。
