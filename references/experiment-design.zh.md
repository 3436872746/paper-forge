# 实验设计

## 1. 臂与控制组

每个批次都包含：

- **处理臂（treatment）**；
- 至少一个**安慰剂/相同臂（placebo / identical）**（同样的代码，不同的标签），用来度量运行间地板（run-to-run floor）；
- 当主张是关于一个估计时，需要**oracle 臂**（它界定了任何排序方式所能达到的上限）。

给那个*无法*对自变量作出响应的臂命名。如果没有这样的臂，这个设计就无法把信号从噪声中分出来。

## 2. 预登记判据

在运行之前，写进批次头部：

- P1..Pn：机制得到支持所必须成立的条件；
- 每个指标的地板；
- 什么算作"无法区分"；
- 聚合约定（用哪个中位数、分析哪些轮次）。

运行之后，判据不能新增。一个在不同指标上触发的判据不算数。

## 3. 批次清单

每个批次写出 `meta.txt`，包含：

```
script, git commit, date, OUT, N, K, load/rho, model, quantization,
seeds, rounds analysed, environment (engine version), expected model
```

批次无法观测到的任何东西（模型、引擎标志）都必须**声明、在启动前守卫、并记录**。守卫方式：查询引擎的 `/v1/models`，不一致就拒绝运行。

## 4. 输出纪律

- 每次运行都得到一个新的 `OUT`；重跑必须显式地不同。
- 如果 `OUT` 已存在且未被声明为复用，批次脚本必须大声失败。
- 长作业：`setsid nohup ... > out.txt 2>&1 < /dev/null &`。
  `[1]+ Done` 是父进程退出；用 `pgrep -af 'bash run_'` 并数日志里已完成的记录来核实。
- 批次运行期间，不要启动、停止或探测任何与该引擎共享的东西。

## 5. 共享机器

- 绝不按宽模式杀进程。`pgrep -af` → 挑准那个 PID → 杀 → 再检查。
- 优先使用你自己的启动器写出的 pidfile；退而求其次，用一个只有你的项目使用的端口。
- 清理范围 = 本次会话创建的东西。如果归属不清，打印清单然后停下。

## 6. 可复现性

- 钉住种子；记录每个臂的轮次顺序。
- 论文工件只有在经过一次**从零构建（from-zero build）**之后才被接受：解压提交包，运行文档里的命令，得到相同的页数和相同的数字。
- 把分析脚本留在仓库里；没有脚本的数字是传闻。

## 7. 负面与作废批次

记录每一个失败或作废的批次：

```
batch id | why void | what it can still be cited for | replacement batch
```

一个没有被记录的作废批次，会在六周后被引用。
