# 可复现性与运维（Reproducibility and operations）

**这一页是干什么的**：它讲怎么让论文里的每个数字都能重新算出来，以及怎么在服务器上安全地跑长任务。两边合起来是同一件事：别人能复现，你也不闯祸。

**什么时候看它**：你要写论文里的统计数字的时候；你打包投稿材料、准备给别人跑的时候；你要提交长批次的时候；你发现服务器显存被占满的时候；你要给一批结果做版本的时候。

## 1. 产物：脚本、数据、验证脚本

**做什么**：让每一个报告出来的数字都有出处，而且能被重算。

- 分析脚本与数据放在一起；每一个报告出来的数字都由某个脚本产生。
- 维护一个 `verify.py`，它从原始文件重新计算每个头条数字，并打印一张通过/失败表。
- 论文产物只有在经过一次**从零构建（from-zero build）**之后才算"完成"：解压到一个空目录，运行文档化的命令序列，得到相同的页数和相同的数字。

**例子**：论文里写"p99 延迟降低 23%"。`verify.py` 从 `runs/*.csv` 重算这个数，打印 `p99_reduction: PASS`。把 zip 解压到另一台机器再跑一遍，数字应当一样。

**为什么**：投稿、rebuttal、终稿版（camera-ready）之间常隔几个月。脚本是唯一还记得当时算法的东西。

## 2. 构建卫生（build hygiene）

**做什么**：让 PDF 里的引用编号和参考文献始终对得上。

- 改动了影响引用的文字后，**重新运行 bibtex**。一份过期的 `.bbl`（BibTeX 生成的参考文献列表文件）会让 PDF 看起来正常，编号却还是旧的。
- 编号按首次使用顺序；如果某张表在 Table I 出现之前就被引用，要么移动这个浮动体，要么改成指向该小节。
- 干净构建之前删掉旧的 `.aux/.bbl/.out`；否则缺失的引用可能被掩盖。`.aux` 是 LaTeX 记交叉引用的中间文件。

**例子**：在引言里删掉一段带 `\cite` 的文字，然后只跑了 `pdflatex`。PDF 能打开，但 [7] 指向的已经是上一版的内容。正确做法是跑 `bibtex`，再跑两遍 `pdflatex`。

**为什么**：LaTeX 不会因此报错，它只是沿用旧文件。错误藏在"看起来正常"里。

## 3. 长任务（long jobs）

**做什么**：让任务脱离终端独立跑，并用两个信号确认它真的跑完了。

- `setsid nohup cmd > out 2>&1 < /dev/null &`
- `[1]+ Done` 表示父进程退出了，而不是任务跑完了。
- 用两个独立信号验证：一次进程检查加一次记录计数。
- 批次运行期间：只读已经写好的文件。

**例子**：命令跑起来后关掉 SSH。第二天用 `pgrep -af` 看进程还在不在，再数输出目录里新增了几个结果文件。两个都对上，才算完成。

**为什么**：`nohup` 只保证挂断不杀进程，不保证进程没崩。进程和计数一起看，才不会把崩溃当成完成。

## 4. 共享服务器（shared servers）

**做什么**：只动自己的进程，别人的一个都不碰。

- 绝不用宽模式的 `pkill -f`。`pgrep -af` -> 精确 PID -> kill -> 复查。PID 是进程编号，`pkill -f` 按命令行文字匹配，会误伤同名的别人进程。
- 优先用启动时写下的 pidfile；退而求其次，用属于本项目的某个端口。pidfile 是启动时把 PID 写进去的小文件。
- 不要为了腾出设备而停掉别人的引擎；等待或询问。

**例子**：显存满了，先 `pgrep -af` 看清每一行命令行，确认 PID 是自己的批次再 kill。如果那行是别人的实验，就等，或者去问。

**为什么**：共享机器上一次误杀，可能毁掉别人跑了一周的批次。按 PID 杀，范围才可控。

## 5. 快照与版本（snapshots and versions）

**做什么**：给每次运行的产物一个版本号，并把当时的环境记下来。

- 产物按日期/字母编号版本；绝不用 "final"。
- 一份清单（manifest，列出包内和包外文件的目录）列出被排除在仓库之外的大文件。
- 把确切的环境（引擎版本、模型、量化 quantization）写进 `meta.txt`；批次自己观察不到这些。量化（quantization）是把模型权重压成更低精度以省显存的做法。

**例子**：结果目录叫 `results/20260314a/`、`results/20260314b/`。`manifest.txt` 里写 `*.safetensors 未入库，见 /data/models/`。`meta.txt` 里写引擎版本、模型名和量化方式。

**为什么**：三个月后重跑，你会忘了当时用的是哪个权重。`meta.txt` 是唯一能回答的地方。

## 一页速查

- 每个数字都由脚本产生，脚本放在数据旁边。
- 用 `verify.py` 从原始文件重算头条数字，打印通过/失败。
- 从零构建：空目录解压、按文档跑命令、页数和数字都对。
- 改了引用文字就重跑 bibtex；过期的 `.bbl` 不报错。
- 干净构建前删掉旧的 `.aux/.bbl/.out`。
- 长任务用 `setsid nohup`；`[1]+ Done` 不等于跑完了。
- 用进程检查和记录计数两个信号确认完成。
- 绝不 `pkill -f`；`pgrep -af` 定位 PID 再杀。
- 优先 pidfile；不碰别人的引擎。
- 产物按日期/字母编号，环境写进 `meta.txt`。
