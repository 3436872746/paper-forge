# 回复审稿人（Responding to reviewers）

**这一页是干什么的**：它教你把审稿意见分成三类，并按固定顺序处理。核心顺序是：先核实，再改稿，最后才决定要不要补实验。

**什么时候看它**：你刚收到审稿意见的时候；你拿不准某条意见该改还是该回的时候；你想加实验但不确定值不值的时候；你在写回复信（response letter，逐条答复审稿意见的文档）的时候；审稿人说"我们复现不出来"的时候。

## 1. 把每条意见分进三个桶之一

**做什么**：逐条读意见，先贴标签，再动手。

1. **事实缺陷（factual defect）**——一个数字、一条引用、一处论断/证据不匹配。拿产物（编译后的 PDF / 源码 / 原始文件）去核实，修好，并说明改了什么。核实之前不要争辩；若干"缺陷"是误读，也有若干是真的。
2. **叙事框架分歧（framing disagreement）**——审稿人想要另一个故事或范围。判断论文能否承载它。如果不能，就在 Limits 一节写明范围，并在回复信里回答；不要悄悄改动论断。Limits 是论文里专门讲局限的那一节。
3. **超出范围（out of scope）**——新系统、新负载、硬件研究。先说明这一点，然后提供能界定该顾虑的最便宜的证据（在已有数据上做事后统计量，或一个明确标注的模拟）。事后统计量是用已有数据重新算的指标；模拟是用人工生成的数据代替真实系统跑一遍。

**例子**：审稿人说"Table 2 的加速比与正文不一致"。这是事实缺陷：打开仓库里的结果文件重算，看是表错还是正文错。

审稿人说"应该在 ARM 上再测一遍"。这是超出范围：在 Limits 里写明只测了 x86，再引一条已有文献界定该顾虑。

**为什么**：三类问题要用三种完全不同的回应。分错桶，一个改数字的事会被拖成一场辩论。

## 2. 按固定顺序处理

**做什么**：先核实，再改稿，最后才谈新实验。

1. 从产物核实每一处被指称的错误；记录判定（真 / 不真）。
2. 对真实错误，修好并记录根因（root cause，错误产生的真正原因，见 `gates.md`）。
3. 对框架问题，写好将要出现在 Limits 里的那一段。
4. 只有到这之后，才判断是否需要新实验。

**例子**：把每条意见抄进一张表，四栏：意见、桶、判定、动作。四栏填完再动笔改论文。被指"数字不对"的意见里，常常有一半在核实这一步就消失了。

**为什么**：先改后核，会把本来没问题的段落改坏。核实的成本远低于改稿。

## 3. 什么时候值得做新实验

**做什么**：用四个条件筛，四条全中才开新的批次。

新实验在有如下条件时才成立：

- (a) 审稿人给出的替代解释是可信的；
- (b) 它能在现有设置内回答；
- (c) 其成本是有界的；
- (d) 无论答案如何都会改变论文中的某一句。

否则，就用已有数据回答。

**例子**：审稿人说"提升可能只来自更大的批次，而不是你的调度器"。这个替代解释可信（a）；在现有设置里加一组大批次基线就能回答（b）；机时有限（c）；答案会改掉贡献列表里关于调度器的那句话（d）。四条全中，做。

若审稿人问"在别的加速器上如何"，（b）不成立，不做。

**为什么**：缺了（d），实验做完论文一个字都不用改。那笔机时就是白花的。

## 4. 回复信（response letter）

**做什么**：一条意见一个编号条目，写清改了什么，或者为什么没改。

- 每条意见一个编号条目；用一行引述该意见。
- 陈述：我们改了什么（第几节/第几页），或者为什么没改。
- 对负面结果，直说：它界定了方法的边界，并不推翻该发现。
- 绝不要承诺一个你还没算出来的数字。

**例子**：审稿人 2 的第 3 条意见，就写成 "#R2-3"，下面先用一行原文引述，再写"我们在第 5.2 节补充了分类别结果，见 Table 3"。不要写"我们会考虑"。

**为什么**：审稿人和 AC（area chair，领域主席）按编号逐条核对。少一个编号，就等于有一条意见没回。

## 5. 反复被证实的事情

**做什么**：把这些当成投稿前的自查清单。

- 审稿人在*句子*上常常是对的，在*系统*上是错的。
- 一个需要四个条件同时成立的论断，会被读成无条件的。
- 只出现在一个聚合指标里的结果会掩盖类别级（class-level）或尾部（tail）效应；在审稿人开口之前就补上第二个指标。聚合指标是把所有样本合成一个平均数的那种指标；类别级是单独看某一类样本，尾部是只看最慢或最差的那一小撮。
- 审稿人说"我们复现不出来"，通常意味着描述不完整，而不是结果有假。

**例子**：论文写"在 A、B、C、D 都满足时方法有效"，审稿人读成"方法总是有效"。把条件写进句子的主语，或在 Limits 里重述。再比如只报平均吞吐，某一类请求的延迟翻倍会被平均值吃掉，补一张分类别的表。

**为什么**：这些不是运气问题，是写作和统计的固定漏洞。提前补，比 rebuttal（答复阶段）时补便宜得多。

## 一页速查

- 每条意见先分桶：事实缺陷、框架分歧、超出范围。
- 事实缺陷先核实再争辩；一半是误读。
- 框架分歧写进 Limits，不悄悄改论断。
- 超出范围就说清楚，再给最便宜的证据。
- 处理顺序：核实 → 改稿 → 写 Limits → 才考虑新实验。
- 新实验要四条全中，尤其（d）：答案会改论文里的某一句话。
- 回复信一条意见一个编号，先说改了什么、第几节。
- 负面结果直说它界定了边界，不推翻发现。
- 不承诺还没算出来的数字。
- 审稿人往往在句子层面对、在系统层面错。
