# 回复审稿人（Responding to reviewers）

## 把每条意见分进三个桶之一

1. **事实缺陷（Factual defect）**——一个数字、一条引用、一处论断/证据不匹配。
   拿产物（编译后的 PDF / 源码 / 原始文件）去核实，修好，并说明改了什么。核实之前不要争辩；
   若干"缺陷"是误读，也有若干是真的。
2. **叙事框架分歧（Framing disagreement）**——审稿人想要另一个故事或范围。
   判断论文能否承载它。如果不能，就在 Limits 一节写明范围，并在回复信里回答；不要悄悄改动
   论断。
3. **超出范围（Out of scope）**——新系统、新负载、硬件研究。
   先说明这一点，然后提供能界定该顾虑的最便宜的证据（在已有数据上做事后统计量，或一个明确
   标注的模拟）。

## 工作顺序

1. 从产物核实每一处被指称的错误；记录判定（真 / 不真）。
2. 对真实错误，修好并记录根因（见 `gates.md`）。
3. 对框架问题，写好将要出现在 Limits 里的那一段。
4. 只有到这之后，才判断是否需要新实验。

新实验在有如下条件时才成立：(a) 审稿人给出的替代解释是可信的，(b) 它能在现有设置内回答，
(c) 其成本是有界的，(d) 无论答案如何都会改变论文中的某一句。否则，就用已有数据回答。

## 回复信（Response letter）

- 每条意见一个编号条目；用一行引述该意见。
- 陈述：我们改了什么（第几节/第几页），或者为什么没改。
- 对负面结果，直说：它界定了方法的边界，并不推翻该发现。
- 绝不要承诺一个你还没算出来的数字。

## 反复被证实的事情

- 审稿人在*句子*上常常是对的，在*系统*上是错的。
- 一个需要四个条件同时成立的论断，会被读成无条件的。
- 只出现在一个聚合指标里的结果会掩盖类别级（class-level）或尾部（tail）效应；在审稿人开口
  之前就补上第二个指标。
- 审稿人说"我们复现不出来"，通常意味着描述不完整，而不是结果有假。
