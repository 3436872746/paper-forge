# paper-forge · 中文说明

> 一套给**实证类计算机系统论文**（系统、网络、体系结构、ML 系统、安全）用的"生产线"：
> 阶段 + 闸门 + 统计规矩 + 可复用脚本 + 一份"沉默陷阱"案例库。
>
> 它**不是**论文摘要合集，也**不是**写作模板库。里面每一条规则都来自一次**没有报错、却悄悄把结果写错**的真实事故。
>
> 英文版见 [README.md](README.md)。这份中文说明是给零基础的同学看的：先读这一份，再按需翻目录里的东西。

---

## 一、这能干什么（你会在什么场景下用它）

把它想成一位"带过很多届学生的师兄"，在你做下面这些事的时候站在旁边提醒你：

| 你要做的事 | 它会帮你做什么 | 你会拿到什么 |
|---|---|---|
| **定选题 / 写 claim** | 逼你把主张写成一句**可证伪**的话，并指出"如果这条不成立，哪个实验会当场暴露它" | 一个能进 Introduction 第一段的核心句 + 反例条件 |
| **设计一批实验** | 检查你的实验里有没有**对照臂 / 安慰剂臂 / 地板 / 配对单元 / 预注册判据**；缺哪个补哪个 | 一张"臂 × 控制变量 × 判据"的执行表 |
| **跑批次** | 提醒 `OUT` 覆盖、`meta.txt`、种子、并发干扰、长任务挂断等**会静默毁掉整批数据**的坑 | 可复现的批次清单（manifest） |
| **分析数据** | 告诉你该用配对统计还是置换检验；什么差异**低于地板就不许写成"有差异"** | 一张"数字 → 来源文件 → 复算脚本"的追溯表 |
| **写论文** | 标题、摘要五句、引言六段、贡献写法、局限写法，逐节给结构和反例 | 一份照着就能落笔的骨架 |
| **做图** | 矢量优先、一图一个结论、图注写结论不写面板、图也要算进页数预算 | 图规格清单 + 常见坏图对照 |
| **投稿前检查** | 页数、引用顺序、匿名、作者/COI、版权块、从零编译 | 一份机械审计报告（脚本能自动跑一部分） |
| **回评审意见** | 把每条意见分到"能立刻答 / 要补实验 / 只能承认边界"三类，并给回复信结构 | 分桶清单 + 回复信骨架 |
| **找灵感 / related work** | 250 篇近三年论文的**设计招式卡片**（问题 → 假设 → 机制 → 证据 → 边界 → 可偷的一招） | 按阶段检索的"招式库"，写 related work 时先定位再读原文 |

**它不替你做的事**：不替你跑实验、不替你读原文、不替你判断你的数据意味着什么。
所有卡片只从**摘要**提炼；凡是摘要里没写的，卡片里就写 "not stated in abstract"。**引用一条机制之前，必须回去读论文正文。**

## 二、三分钟上手

### 2.1 装进 Claude Code

把这个目录整个复制到技能目录（目录名必须叫 `paper-forge`）：

```bash
# 个人级（所有项目都能用）
cp -r paper-forge ~/.claude/skills/paper-forge

# 或者项目级（只在这个仓库里用）
cp -r paper-forge <你的仓库>/.claude/skills/paper-forge
```

Claude Code 会自动发现 `SKILL.md`。之后你不需要记任何命令，**用自然语言说出你的任务**就会触发，例如：

- "帮我看这段摘要有没有把结论说过头"
- "下周要跑一批实验，帮我按闸门逐条检查计划"
- "评审说我们的 baseline 不公平，帮我分类并起草回复"
- "这篇论文的 related work 应该怎么摆轴"

### 2.2 不用 Claude Code 也能用

全部内容是**纯 Markdown + Python 标准库脚本**。没有大模型也能当手册读：

- 想学怎么写系统论文 → 读 `references/writing.md` + `templates/abstract_intro.md`
- 想知道哪些坑会静默出错 → 读 `references/casebook.md`（99 行，40 个陷阱，每个一行检查）
- 想找设计灵感 → 读 `references/idea-cards/design-moves.md`（40 条去重后的招式）

### 3.1 论文卡片库 `references/idea-cards/`

```
idea-cards/
├── README.md                     语料选择口径 + 卡片字段说明 + 使用方式
├── _corpus.json                  主语料：100 篇（2023–2026，系统/ML 顶会）
├── _batch1..5.json               蒸馏时的输入切片
├── cards_batch1..5.md            100 张卡（每批 20 张）
├── design-moves.md               ★ 读完全部卡片后去重出的 40 条"可偷的招式"
└── domains/                      ★ 三个专题包，各 50 篇（同样格式）
    ├── llm_sched/                LLM 推理调度（KV cache、SLO、PD 分离、批调度）
    ├── video_sat/                视频传输 / 卫星网络（ABR、低延迟、LEO、多路径、QoE）
    └── security/                 网络安全（提示注入、越狱、对抗、侧信道、fuzz、供应链）
```

每张卡的七个字段：

| 字段 | 回答什么 | 怎么用 |
|---|---|---|
| **Problem** | 它打的是什么问题 | 判断和你是否同一个问题 |
| **Assumption** | 它**默认**了什么才敢这么做 | ★ 最容易借来当"你的假设攻击点" |
| **Mechanism** | 它具体怎么做的（一句话） | 决定能不能搬到你的场景 |
| **Evidence** | 它用什么证据撑住（真机 / 仿真 / trace / 回放） | 判断证据层级够不够 |
| **Boundary** | 作者自己承认的边界；摘要没写就写 not stated | 写 related work 时用来划界 |
| **Stealable move** | **唯一鼓励直接复用的字段**：去掉领域后仍然成立的那一招 | 设计新实验/新机制时先扫这一栏 |
| **Pitch** | 它自己怎么一句话卖这个工作 | 学"贡献句"的句式 |

> ⚠ 卡片是从**摘要**生成的。它够你判断"要不要读这篇"，不够你引用它的机制。
> 写进论文的每一条机制，都要回原文核。

## 四、里面到底做了什么（方法，不是口号）

### 4.1 六阶段流水线

| 阶段 | 目标 | 出门条件（不过不许进下一阶段） |
|---|---|---|
| 0. 定框 | 一句话主张；什么会证伪它；贯穿全文的例子 | 主张可证伪，且有反例臂 |
| 1. 设计 | 臂、对照、安慰剂、配对单元、预注册判据 | 每条臂都有地板；每条判据在跑之前就写死 |
| 2. 跑批 | 显式 `OUT`、`meta.txt`、种子、互不干扰 | 批次能从 manifest 复现 |
| 3. 分析 | 配对统计、置换地板、剂量-反应 | 每个数字都能追到文件和脚本 |
| 4. 写作 | 标题 → 摘要 → 引言 → 证据 → 局限 | 读者十分钟内能说出主张和边界 |
| 5. 投稿 | 模板、页数、文献、匿名、COI | 从零编译能复现 PDF；机械审计全绿 |

### 4.2 九道闸门（每次动手前过一遍）

A 用已知答案的输入干跑 · B 安慰剂臂与地板 · C 同状态读数 · D 判据本身还是它的历史取值 ·
E 这个指标在自动核对清单里吗 · F 两个变量是否一起变了 · G 数字回源头算过吗 · H 断言前 grep 过吗 ·
I "干跑"会不会碰真进程/真文件。

展开与实例：`references/gates.md`。

### 4.3 统计默认值（系统论文口径）

- 分析单元是**一次运行（或一个种子）**，不是一条请求。
- 区间默认写**配对逐次差值的最小–最大值**；写 CI 必须标出来。
- 必须有**同配置的空跑地板**；低于地板的差异不叫差异。
- 不烧机时的比较（仿真、离线回放）用**置换检验**。
- 区分"两两反转"与"整类分离"，两个都报。
- 报 n、种子数、聚合口径（下中位数还是插值中位数）。

细节：`references/stats.md`、`references/experiment-design.md`。

### 4.4 案例库怎么来的

`references/casebook.md` 的 40 条，对应的是 40 次真实踩坑，例如：

- 延迟全是 0、失败恰好为 0 —— 不是完美，是**引擎已经死了**，代理把故障伪装成了成功。
- 批次脚本写好了、台账记了"已完成"，**一次都没跑过**。
- 按印象写过滤值（以为列里是 `success`），实测只有两种值，**一次剔光 143 万条**。
- 两个变量一起变，却把效果归因给其中一个。
- 摘要里三处数字，两处是上一版实验留下的。

每一条都配一行**可执行检查**，不是"注意一下"。

## 五、四个脚本怎么用

```bash
# 1) 引用与标签审计：在论文目录里跑
python scripts/check_refs.py main.tex main.bbl

# 2) 页数与版式审计：传编译出的 PDF
python scripts/page_audit.py build/main.pdf

# 3) 配对统计：输入两列数（每行一对），打印差值区间和置换 p 值
python scripts/stats_paired.py a.txt b.txt

# 4) 从零编译一个投稿包并审计
bash scripts/build_from_zero.sh submission.zip main.tex
```

三个 Python 脚本**只用标准库**，Python 3.8+ 直接跑；不需要装 numpy/scipy。

## 六、一次完整的使用示例

假设你下周要交一篇六页短文：

1. **定框**：把 claim 写成一句可证伪的话；写下"如果对照组不输，这句话就错"。
2. **设计**：跑 `references/experiment-design.md` 的清单，补上安慰剂臂和地板；判据先写死。
3. **跑批**：按 `reproducibility.md` 建 `OUT=.../batch_2026xxxx`，写 `meta.txt`（命令、commit、种子、机器）。
4. **分析**：`stats_paired.py` 出配对区间；低于地板的差异删掉，不写。
5. **写作**：`templates/abstract_intro.md` 填五句/六段；贡献写成"发现"不写"模块"。
6. **做图**：`figures.md` 过一遍；每张图回到 100% 缩放看字。
7. **投稿**：`submission.md` 清单 + `check_refs.py` + `page_audit.py` + `build_from_zero.sh`。
8. **回评审**：`review-response.md` 三桶分类，先答"能立刻答"的。

## 七、维护与贡献

- **发现新的沉默陷阱** → 加进 `references/casebook.md`，格式：**症状 / 为什么没报错 / 一行检查**。
- **发现新的可偷招式** → 加进对应域包的 `design-moves.md`，并注明来自哪张卡。
- **加一个专题域** → 在 `references/idea-cards/domains/<name>/` 下放 `_corpus.json`（字段见现有文件）+ `cards_batchN.md` + `design-moves.md`。
- 原则：**只收"会静默出错"的规则**。会报错的坑不值得写进来，编译器会替你抓。

## 八、边界（先说清楚）

- 卡片只来自摘要，**不是**论文精读笔记；引用前必回原文。
- 统计建议面向"系统论文的少量重复运行"，不适用于大规模 A/B 平台实验。
- 模板是 IEEE 会议六页起步件，投其他模板时保留结构、替换导言。
- 本仓库不包含任何未发表论文的数据、结论或草稿。
