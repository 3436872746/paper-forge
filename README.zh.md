# paper-forge：从选题到投稿，一套能照着做的科研流程

这份文档是给**没写过论文、也没做过实验**的同学看的。
不要求你先懂任何术语：每一步都写清楚「做什么 → 为什么 → 打开哪个文件 → 做到什么程度算过关」。

如果你只想快速知道它是什么：

> 它是一本**操作手册**（Markdown 文件）+ 一组**自动检查脚本** + 一个**论文点子库**。
> 你按下面 10 步走，卡住了就翻对应的那一页；写进论文的每个数字，都能追到文件和脚本。

---

## 一、先看全貌：一篇论文要走的 10 步

```
 1 选题          2 查文献        3 写一句主张
    ↓               ↓               ↓
 4 设计实验  →   5 跑实验   →    6 分析数据
                                    ↓
 7 画图      →   8 写作     →    9 投稿前检查  →  10 回评审/归档
```

- 第 1–3 步通常 1–2 周（想清楚比跑得快重要）。
- 第 4–6 步是实验周期，取决于机器；**这段时间最容易白烧机时**，所以第 4 步要过闸门。
- 第 7–9 步通常 2–4 周。
- 第 10 步是把这次踩的坑写回手册，下次不再踩。

> 下面每一步都按同一个格式写：
> **要做什么** / **为什么** / **打开哪个文件** / **过关判据**。
> 过关判据不过，就先别进下一步。

---

### 第 1 步：选题

**要做什么**
用一个句子写出你想回答的问题，并且写出「什么结果会证明我想错了」。

例子（通用，不是任何人的论文）：
- 问题：把缓存分成大小两级之后，未命中率会下降吗？
- 反例：如果两级和一级的未命中率差距落在同配置重复运行的自然波动内，就算没差别。

**为什么**
没有反例的问题，做完了也不知道算不算成功；评审第一个问的就是这个。

**打开哪个文件**
`references/writing.md` 的「Title」一节；`templates/abstract_intro.md` 的第一句。

**过关判据**
你能用一句话说出「这句话如果错了，会是哪个实验显示出来」。

---

### 第 2 步：查文献（别跳过）

**要做什么**
找出这个问题上已经有哪些工作，并把它们放到一张「轴」上：谁在解决同一个问题的不同侧面，谁的方法你打算借。

**为什么**
90% 的「新想法」其实是别人做过的换皮；查文献是在保护你的时间，不是在走过场。

**打开哪个文件**
- `references/literature-review.md`：从问题到检索词、两轮筛选、triage 表、引用核验、停止规则。
- `references/idea-cards/INDEX.md`：250 篇论文清单（标题 + 会议 + 年份 + DOI）。
- `references/idea-cards/design-moves.md` 与三个域包的 `design-moves.md`：别人论文里「可以偷的一招」。
- `references/writing.md` 的「Related work」一节。

**过关判据**
你能说出 3 篇最接近你的工作，以及你和它们**各自差在哪一句话上**。
（写不出这句话，说明还没读懂，不要开始做实验。）

---

### 第 3 步：写一句主张（claim）

**要做什么**
把第 1 步的问题，变成一个可检验的主张：**在什么条件下，做什么改动，会导致什么可测量的变化**。
再写清楚这个变化**用什么指标测**、**多大才算大**。

**为什么**
主张不清楚，实验就会越加越多，最后每个都只能说「有点提升」。

**打开哪个文件**
`references/writing.md` 的「Abstract — five sentences」；`templates/abstract_intro.md`。

**过关判据**
主张里同时有：条件、改动、指标、阈值。四样缺一，回去补。

---

### 第 4 步：设计实验

**要做什么**
在跑任何东西之前，先把下面五样写在纸上：

1. **实验臂**：你要比的几组（比如 A 方案 / B 方案 / 什么都不做的对照组）。
2. **对照与安慰剂**：一组「代码一样、只换个名字」的空跑，用来测噪声。
3. **地板**：空跑两次之间的差异有多大。比这个小的差异，不许写成「有差异」。
4. **配对单元**：以什么为单位配对（一次运行？一个种子？），不能拿单条请求当独立样本。
5. **判据**：跑之前就写死「多少算成功」，跑完不许改。

**为什么**
这五样是「结果出来后才发现没法解释」的唯一解药；补做实验的成本是原来的好几倍。

**打开哪个文件**
`references/experiment-design.md`（第一到第三节）；`references/gates.md` 的 B（安慰剂）、C（同状态读数）、F（两个变量一起变）。

**过关判据**
把这张表拿给同组的人看，他能不问你、直接照着跑。

---

### 第 5 步：跑实验

**要做什么**
每一批实验都新建一个输出目录，并在里面放一张「批次卡」：跑的什么命令、用哪个代码版本、什么种子、哪台机器、什么时候。

**为什么**
不写批次卡，两周后你就不记得这个数是哪次跑的了；更糟的是重跑会**静默覆盖**上一批原始数据。

**打开哪个文件**
`references/reproducibility.md`；`references/casebook.md` 的「Data and batches」一节。

**过关判据**
只看这个目录，别人（或三个月后的你）能原样再跑一遍。

> 长任务必须放后台并重定向日志，否则终端一关就全没了。手册里有现成写法。

---

### 第 6 步：分析数据

**要做什么**
1. 先算**配对差**（同一次运行里两组的差），再算区间。
2. 和**地板**比：小于地板的不写。
3. 不是烧机时的比较（仿真、离线回放），用**置换检验**，并在文里注明。
4. 每个写进论文的数字，标注它来自哪个文件、由哪个脚本算出。

**为什么**
系统论文最常见的退稿理由不是方法差，是「这个差异看起来像噪声」。

**打开哪个文件**
`references/stats.md`；`scripts/stats_paired.py`（不用装 numpy/scipy）。

**过关判据**
随机抽论文里 3 个数字，你能在 5 分钟内从原始文件复算出来。

---

### 第 7 步：画图

**要做什么**
一张图只讲一件事；图注写「结论」，不写「左图是 X，右图是 Y」；先出矢量图（PDF/SVG），再看 100% 缩放下字是否清楚。

**为什么**
评审看论文的顺序常常是：标题 → 图 → 图注 → 摘要。图讲不清，正文白写。

**打开哪个文件**
`references/figures.md`；需要更专业的图时配合 `schematic-figure`、`dataviz`、`pdf-figure-vector` 三个技能。

**过关判据**
把图单独发给同组的人，他能说出你想让他记住的那句话。

---

### 第 8 步：写作

**要做什么**
按顺序写，不要从引言开始：

1. **标题**：研究什么、在什么条件下。
2. **摘要五句**：问题 / 发现 / 机制 / 设计上的回应 / 边界。
3. **引言六段**：假设 → 用例子讲发现 → 为什么调参救不了 → 你用的不同信号 → 证据与边界 → 贡献。
4. **贡献**：写「发现了什么」，不写「做了哪个模块」。
5. **局限**：集中写在一节，别在每节都道歉一遍。

**为什么**
这个顺序让你先想清楚「结论是什么」，再去铺路；反过来写，一定会写成流水账。

**打开哪个文件**
`references/writing.md`；`templates/abstract_intro.md`；改语气时用 `anti-defensive-writing` 技能。

**过关判据**
一个没看过你实验的人，读 10 分钟能说出你的主张和它成立的条件。

---

### 第 9 步：投稿前检查

**要做什么**
跑三个脚本 + 一张清单：

```bash
python scripts/check_refs.py main.tex main.bbl   # 引用顺序/未定义引用/占位符
python scripts/page_audit.py build/main.pdf      # 页数/超框/参考文献页
bash   scripts/build_from_zero.sh submission.zip # 从零编译 + 复跑上面两项
```

再按 `references/submission.md` 逐条过：页数、模板、匿名（双盲）、作者与利益冲突、版权块、附录。

**为什么**
这些错误全部机械可查，但每一条都能让论文在形式审查阶段被退回。

**打开哪个文件**
`references/submission.md`；`templates/ieee6p.tex`（干净的 IEEE 六页起步模板）。

**过关判据**
从零解压一个包，能编出一模一样的 PDF，且三项检查全绿。

---

### 第 10 步：回评审、归档

**要做什么**
把每条评审意见分三类：**能立刻答的** / **要补实验的** / **只能承认边界的**。
按这个顺序处理；补实验的先进第 4 步重新设计，不要直接改文字糊过去。
最后，把这次踩到的新坑写进 `references/casebook.md`（格式：症状 / 为什么没报错 / 一行检查）。

**为什么**
评审意见里最危险的是「听起来对、但你的数据其实不支持」的那一条；分类能防止你条件反射地辩解。

**打开哪个文件**
`references/review-response.md`。

**过关判据**
回复信里每条意见都有明确去向，没有一条是「我们会考虑」。

## 二、卡住了怎么查（按症状找）

| 你遇到的情况 | 翻这一页 |
|---|---|
| 数字好得不像真的（延迟≈0、失败恰好 0） | `references/casebook.md` → Measurement |
| 两个东西一起变了，不知道是谁的功劳 | `references/gates.md` → F |
| 评审说 baseline 不公平 | `references/review-response.md` |
| 论文超页 / 图放不下 | `references/submission.md`、`references/figures.md` |
| 引用顺序乱、有未定义引用 | 跑 `scripts/check_refs.py` |
| 不知道下一批实验该加什么对照组 | `references/experiment-design.md` |
| 想找相关工作和可借的招 | `references/idea-cards/INDEX.md`、各 `design-moves.md` |

## 四、三种用法

1. **完全新手**：从第 1 步走到第 10 步，每步只看指定那一个文件。
2. **已经在写论文**：直接跳到卡住的那一步；先跑第 9 步的三个脚本。
3. **只想找点子**：读 `references/idea-cards/design-moves.md` 和各域包的 `design-moves.md`，
   每条招式后面都标了来自哪张卡，再去 `INDEX.md` 找原文。

## 六、术语小词典

| 词 | 一句话解释 |
|---|---|
| 实验臂（arm） | 你要比较的每一组配置 |
| 对照组 / baseline | 现在大家用的做法，用来证明你更好 |
| 安慰剂 / 空跑 | 代码完全一样、只改个名字的一组，用来测「没有差别时差异有多大」 |
| 地板（floor） | 空跑两次之间的自然波动；小于它的差异不算差异 |
| 配对（paired） | 在同一次运行/同一个种子里比较两组，而不是各跑各的再比平均 |
| 置换检验 | 把标签随机打乱很多次，看真实差异是否比随机还大（不烧机时的标准做法） |
| 预注册判据 | 跑之前就写死「多少算成功」，防止跑完再改标准 |
| 双盲 | 评审看不到作者和单位；投稿版要删名字、致谢、项目号 |
| COI | 利益冲突：作者与评审之间的合作关系申报 |
| claim / 主张 | 一句话说清「在什么条件下，做什么，会导致什么可测量的变化」 |

## 七、边界

- 手册面向**实证类**计算机论文（系统、网络、体系结构、ML 系统、安全）；纯理论论文只部分适用。
- 卡片来自摘要，不是精读笔记；引用前回原文。
- 统计建议面向「重复次数不多的系统实验」，不适用于大规模线上 A/B。
